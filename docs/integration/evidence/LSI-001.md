## 3. Root Route (`/`) Reconciliation with `URL_DESIGN.md`

### 3.1 The Conflict
- **Documented Contract (`docs/URL_DESIGN.md` §2):**
  States that `/` (`app/page.tsx`) is a `Root redirect → last active workspace`.
- **Actual Runtime Implementation (`apps/web/src/app/page.tsx`):**
  Mounts `<WorkspaceDashboard />`, which:
  - Fetches and displays the user's workspaces (`mine` and `discover` tabs).
  - Provides a "Create Workspace" action.
  - Mounts `<RoadmapJobsNotice />` to display active/unfinished background generation jobs and allow resumption.
  - Mounts `<RoadmapModal />` for direct roadmap generation.

### 3.2 Reconciled Architectural Decision
The root path `/` is a primary user landing surface, not a silent redirect:
1. **Authenticated Users:** `/` functions as the **Personal Dashboard / Hub**, presenting personal workspaces, active learning enrollments (My Learning), and in-flight generation jobs.
2. **Unauthenticated / Guest Users:** `/` (or `/learn`) serves as the **Public Learning Catalog** landing page, allowing discovery and guest lesson reading without requiring credentials.
3. **Canonical Resource Addresses:** In full alignment with ADR-0006 (`docs/URL_DESIGN.md`), deep entity addresses remain strictly path-based:
   - `/w/{workspaceId}` — Workspace landing.
   - `/w/{workspaceId}/chat/{chatId}` — Root chat / thread view.
   - `/w/{workspaceId}/chat/{chatId}/canvas` — Shared spatial canvas view.
   - `/learn/{slug}` — Public roadmap preview.
   - `/learn/{slug}/lessons/{topicSlug}` — Public lesson view.
   - Transient focus uses query params (e.g., `?node={nodeId}` or `?branch={branchId}`). Primary identities are never stored in query parameters.

## 4. Ownership and Identity Model

To prevent authorization bypasses, data contamination, and accidental leaks between public content and private learner records, the system enforces a strict two-domain ownership boundary:

```mermaid
flowchart TD
  subgraph Public Domain [Public Domain (Read-Only / Unauthenticated)]
    P1[Published Roadmap Template: templateId + snapshotVersion]
    P2[Public Snapshot Metadata: title, slug, summary, category, level, tags]
    P3[Public Lesson Content: topicSlug + versioned markdown]
    P4[Public Sources: title, verified locator, attribution URL]
  end

  subgraph Private Domain [Private Learner Domain (Workspace-Scoped / Authenticated)]
    W1[Learner Workspace: workspaceId]
    W2[Enrollment Copy: roadmapId + revisionId]
    W3[Source Ref: sourceSnapshotRef -> templateId + snapshotVersion]
    W4[Learner Topic Progress: topicId -> not_started | in_progress | completed]
    W5[Practice Attempts: topicId + activityVersion + answers + feedback]
    W6[TopicChat Sessions: sessionId + chatId root node]
    W7[Branch Nodes: parentId + highlightedContext quote]
  end

  P1 -->|Save / Copy Action (LSI-028)| W2
  W2 -.->|Immutable link| W3
```

### 4.1 Invariants
1. **Public Snapshot Immutability:** Published roadmaps cannot be modified in place. Any curriculum update publishes a new `snapshotVersion`.
2. **Private Workspace Isolation:** An enrollment is stored under a learner's `workspaceId`. Progress, personal notes, chat messages, and practice attempts mutate only the private workspace copy.
3. **No Private Leakage in Public APIs:** Public DTOs must never include `workspace_id`, chat/session IDs, user identifiers, internal job IDs, or unpublished notes.
4. **No Public Mutability:** Guests cannot record progress or submit answers without authenticating. If attempted, the UI records a transient intent (LSI-032) and executes it only after sign-in.

## 5. Center Lesson Content: Source Analysis & Decision

### 5.1 Existing Backend Mechanism (`TopicBrief` + `finish_lesson`)
1. **Schema Check (`apps/api/src/schemas/curriculum.py`):**
   - `TopicBrief` returns:
     ```python
     class TopicBrief(CurriculumSchema):
         item: CurriculumItemData
         resources: list[TopicResourceView]
         prerequisites: list[CurriculumItemData]
         progress: TopicProgressData
         default_chat_id: str | None = None
         latest_check: KnowledgeCheckData | None = None
     ```
   - `CurriculumItemData` provides metadata (`title`, `brief` summary up to 4000 characters, `objectives`, `exercise`, `format`, `estimate_minutes`), but **does not contain a complete, authored markdown lesson text**.
2. **Session Lifecycle (`apps/api/src/services/roadmap/tutor.py`):**
   - Opening a topic session starts with `lesson_start_state = "pending"`.
   - Entering the chat triggers `startInitialLesson()`, which requests the LLM to stream an interactive introductory lesson.
   - Upon completion, `finish_lesson()` persists this generated response as an assistant node:
     ```python
     id = f"{row.chat_id}_lesson"
     parent_id = row.chat_id
     role = "assistant"
     content = content  # streamed text
     metadata = {"topicSessionId": row.id, "interrupted": state == "interrupted"}
     ```
   - In existing production, the "lesson" is literally the first assistant message in a dedicated `TopicChat`.

### 5.2 Prototype Mechanism (`apps/web/prototype`)
- The prototype treats lessons as **pre-authored, structured educational content** displayed in a dedicated central `LessonCenter`.
- The `TopicChat` / AI Tutor lives in a side rail alongside the lesson, allowing the learner to read without chat interruption and highlight text to branch into specific questions.

### 5.3 Architectural Decision: Tiered / Hybrid Content Delivery
To achieve the best of both models, the integration will adopt a tiered resolution strategy:
1. **Tier 1 (Authored / Snapshot Lesson Body):**
   - If the curriculum snapshot or topic specification includes an authored markdown body (as with published catalog courses and generated curriculum packages supporting rich lessons), the center reader displays this structured content directly.
2. **Tier 2 (Interactive Tutor Companion):**
   - The right rail hosts the persistent `TopicChat` (`sessionId` / `chatId`), preserving the ability to converse with the AI tutor, highlight lesson text, and create contextual branch nodes.
3. **Tier 3 (Dynamic Fallback for Unauthored Topics):**
   - If a topic has no pre-authored lesson body, the system can leverage the existing `finish_lesson` streaming flow to generate and display the foundational lesson into the topic's root chat, while maintaining compatibility with the center reader interface.
