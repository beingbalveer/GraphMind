## 1. Executive Summary & Objective

In accordance with [LSI-009](file:///Users/balveerd/Documents/AI/GraphMind/docs/integration/LEARNING_STUDIO_BACKLOG.md#lsi-009-learner-completion), the learner completion system has been implemented across full stack:
1. **Authoritative Progress Scoping:**
   - Progress is scoped strictly to `(workspace_id, revision_id, topic_id, owner_id)` in the backend PostgreSQL database (`TopicProgress` table).
   - Authoritative states: `not_started`, `in_progress`, `completed`.
   - `completed_at` timestamp is set upon completion and cleared upon reversion to `in_progress`.
2. **Anti-Mastery Policy Enforcement:**
   - In accordance with the acceptance criteria, completion is **never** called "mastery" or "mastered".
   - The backend validates literals strictly against `{"not_started", "in_progress", "completed"}`; submitting `"mastered"` returns HTTP `422 Unprocessable Entity`.
   - The frontend exclusively displays `"Completed"`, `"Mark as complete"`, and `"In Progress"`.
3. **Concurrency & Rapid Click Protection:**
   - Implemented `useTopicProgress` hook with sequence-based concurrency control (`seqMapRef`).
   - If a learner rapidly clicks completion buttons, older inflight network responses are safely discarded so that stale responses can never overwrite a newer intent.
4. **Optimistic Updates & Resilient Error Recovery:**
   - UI updates optimistically for instant responsiveness.
   - On network or server failure, state is automatically reverted to the previous valid snapshot.
   - An inline error alert banner with a `role="alert"` and an interactive `"Retry"` action appears near the completion control.
   - Authoritative progress counters (`completedCount`, `calculateProgressPercent`) update dynamically.

## 2. Changes Made

### 2.1 Backend Tests & Validation (`apps/api/tests/roadmap/test_progress.py`)
* Added `test_progress_api_ownership_and_validation`:
  - Verified `PATCH /api/v1/workspaces/{workspace_id}/roadmap/topics/{topic_id}/progress` marks topics completed with timestamps.
  - Verified reverting to `in_progress` clears `completed_at`.
  - Verified `"mastered"` is rejected with HTTP 422.
  - Verified unauthenticated / outsider access is rejected with HTTP 401/403/404.

### 2.2 Frontend Hook (`apps/web/src/components/studio/useTopicProgress.ts`)
* Implemented `useTopicProgress`:
  - Tracks `progressMap`, `pendingTopicId`, and `error`.
  - Sequence tracking (`seqMapRef`) to guarantee newer intent is never overwritten by delayed network responses.
  - Exposes `toggleTopicProgress`, `retry`, `clearError`, `completedTopicIds`, `completedCount`, and `calculateProgressPercent`.
