## 1. Executive Summary & Objective

In accordance with [LSI-010](file:///Users/balveerd/Documents/AI/GraphMind/docs/integration/LEARNING_STUDIO_BACKLOG.md#lsi-010-versioned-practice-server-contract), the backend practice and knowledge check contracts have been generalized, versioned, and verified:
1. **Reused Checks Route Boundary:**
   - Extended `/workspaces/{workspace_id}/roadmap/topics/{topic_id}/checks` route to support both versioned practice activities and legacy AI assessments with 100% backward compatibility.
   - Added `GET /workspaces/{workspace_id}/roadmap/topics/{topic_id}/checks` to return the complete topic practice state (`PracticeStateData`: active activity, saved draft, attempt history, and attempts count).
   - Added `PUT /workspaces/{workspace_id}/roadmap/topics/{topic_id}/checks/draft` and `DELETE /workspaces/{workspace_id}/roadmap/topics/{topic_id}/checks/draft` to persist and clear in-progress answer drafts per-learner, per-topic.
2. **Versioned Activity Contract:**
   - Activities carry explicit identity: `id` (e.g. `act_{topic_id}_v1`) and `version` (e.g. `"1.0"`).
   - Activity schemas include `kind` (`choice`, `short_answer`, `reflection`), `prompt`, `choices`, `hint`, and `explanation`.
   - Seeded canonical activities for curated lessons (`py-01` to `py-12`, `a11y-01` to `a11y-03`, `sql-01` to `sql-03`) and dynamic fallback generation for arbitrary generated curriculum topics using `exercise` and `title`.
   - Client responses never leak `correct_choice`.
   - Attempt submissions validate `activity_id` and `activity_version`; mismatches are rejected with HTTP `422 Unprocessable Entity`.
3. **Attempt Identity & Idempotent Duplicate Safety:**
   - Submissions support explicit `attempt_id`.
   - If a duplicate submission with the same `attempt_id` arrives, the existing `KnowledgeCheck` record is returned immediately without creating duplicate database rows or incrementing attempt counts.
   - Retries without `attempt_id` generate new attempt identities and advance the `attempt_number`.
4. **Decoupled Anti-Mastery & Completion Independence:**
   - Submitting an answer or passing a check **never** mutates topic study progress (`TopicProgress.status` remains untouched).
   - Correctness, completion, and mastery stay completely distinct: completion is strictly learner-controlled via LSI-009, and no "mastery" status exists.
5. **No Demo Keyword Grading in Production:**
   - Demo prototype keyword filtering (e.g. `all(term in answer for term in requiredTerms)`) is eliminated. Substantive answers are accepted with constructive rubric explanation feedback.
   - Short answers and reflections validate that substantive content is provided (at least 5 characters).
   - Multiple-choice selections validate against permitted options.
6. **Answer Draft Contract:**
   - Learner answer drafts are persisted in PostgreSQL table `topic_practice_drafts` with an Alembic migration (`20261015_0006_add_topic_practice_drafts.py`).
   - Drafts are cleared automatically upon successful attempt submission.

## 2. Changes Made

### 2.1 Database & Migrations
* Created Alembic migration `apps/api/alembic/versions/20261015_0006_add_topic_practice_drafts.py`:
  - Creates table `topic_practice_drafts` with compound PK `(roadmap_id, topic_id, owner_id)`.
  - Includes foreign keys to `curriculum_items` and `users`, plus index on `(owner_id, roadmap_id)`.
* Added `TopicPracticeDraft` model to `apps/api/src/models/roadmap.py` and exported in `apps/api/src/models/__init__.py`.

### 2.2 Domain Schemas (`apps/api/src/schemas/curriculum.py` & `apps/web/src/lib/roadmapTypes.ts`)
* Added:
  - `PracticeActivityData`: `id`, `version`, `topic_id`, `kind`, `prompt`, `choices`, `hint`, `explanation`.
  - `PracticeDraftRequest`: `activity_id`, `activity_version`, `draft`, `selected_choice`.
  - `PracticeDraftData`: `topic_id`, `activity_id`, `activity_version`, `draft`, `selected_choice`, `updated_at`.
  - `PracticeAttemptData`: `id`, `attempt_id`, `attempt_number`, `activity_id`, `activity_version`, `answer`, `selected_choice`, `correct`, `feedback`, `explanation`, `can_retry`, `next_action`, `submitted_at`.
  - `PracticeStateData`: `topic_id`, `activity`, `draft`, `attempts_count`, `latest_attempt`, `checks`.
  - Extended `CheckRequest`: optional `session_id`, `activity_id`, `activity_version`, `attempt_id`, `answer`, `selected_choice`, `draft`, `is_draft`.
  - Extended `TopicBrief`: added optional `practice_activity`.

### 2.3 Services & Catalog
* Created `apps/api/src/services/roadmap/practice_catalog.py`:
  - Contains `SEEDED_ACTIVITIES` with 18 canonical curriculum activities.
  - Implements `get_topic_activity(topic_id, item_title, exercise)` with dynamic fallback.
* Created `apps/api/src/services/roadmap/practice.py` (`PracticeService`):
  - `get_practice_state`: retrieves activity, draft, and attempt history.
  - `save_draft` / `delete_draft`: manages learner draft lifecycle.
  - `record_attempt`: validates version, dedupes attempt identity, evaluates choices/short answers/reflections without keyword matching, links to primary session, and stores `KnowledgeCheck`.
* Updated `apps/api/src/services/roadmap/curriculum_repository.py`:
  - `read_brief` populates `practice_activity` on `TopicBrief`.

### 2.4 API Endpoints (`apps/api/src/routers/curriculum.py`)
* `GET /topics/{topic_id}/checks`: returns `PracticeStateData`.
* `PUT /topics/{topic_id}/checks/draft`: saves learner draft.
* `DELETE /topics/{topic_id}/checks/draft`: deletes draft.
* `POST /topics/{topic_id}/checks`: handles both versioned practice activities (`body.activity_id`) and legacy session AI checks (`body.session_id`).

### 2.5 Unit & Integration Test Suite (`apps/api/tests/roadmap/test_practice.py`)
* 9 comprehensive tests:
  1. `test_get_practice_state_returns_versioned_activity`: verifies versioned schema and secret answer hiding.
  2. `test_practice_draft_lifecycle`: tests save, retrieve, update, and delete draft lifecycle.
  3. `test_practice_activity_version_validation`: tests 422 on mismatched version or unknown activity.
  4. `test_practice_invalid_answer_rejection`: tests 422 on empty or short (<5 chars) answers.
  5. `test_practice_evaluation_without_demo_keyword_grading`: tests substantive answer evaluation without magic keyword requirements.
  6. `test_practice_does_not_mutate_topic_progress_or_set_mastery`: verifies progress stays decoupled and mastery is never assigned.
  7. `test_practice_duplicate_attempt_identity_safety`: tests idempotent attempt return without row duplication.
  8. `test_choice_activity_evaluation_and_retry`: tests choice selection validation, incorrect retry, and correct resolution.
  9. `test_practice_authorization_isolation`: verifies unauthenticated (401) and viewer access (403).
