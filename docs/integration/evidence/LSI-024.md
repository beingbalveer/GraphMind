## 1. Objective

Make the Learning Studio generation flow resilient to interruption: a refreshed page
resumes the learner's owned in-flight job, cancellation/stale worker attempts cannot publish,
retry semantics are explicit, and a failed profile stays editable instead of being lost.

The backend already provided the durable substrate — owner-scoped `GET /roadmap/jobs` list,
`start`/`retry`/`cancel`, lease-fenced `checkpoint`/`publish`, and explicit retry rules
(`NOT_RECOVERABLE`, `ACTIVE_JOB_EXISTS`, `INVALID_STATE`). This ticket closes the client gap:
the generator previously had **no** resume-on-mount and **no** way to recover a failed
profile, so a refresh lost the run and a terminal failure reset the form to blank.

---

## 2. Changes Made

### 2.1 `apps/web/src/lib/studioGeneration.ts`
* Added `RESUMABLE_JOB_STATUSES` and the pure `resumableJob(jobs)` selector: the newest
  owned **generation** job in a non-terminal status (`queued`/`running`/`awaiting_input`/
  `cancel_requested`). Refinement/promotion jobs and terminal jobs are never resumed.

### 2.2 `apps/web/src/components/studio/StudioRoadmapGenerator.tsx`
* **Resume on mount (refresh recovery):** a one-shot effect lists the learner's owned jobs and,
  when a resumable generation exists, watches it (`useRoadmapJob`) and shows a
  "Resumed your in-progress generation" status line. A resumed run is marked so it never
  auto-navigates on completion (`openedResult` guard) — the learner opens the finished
  roadmap explicitly. A failed list never blocks starting a new roadmap.
* **Failed profile remains editable:** the progress panel now receives `onEditRequest`, which
  resets the idempotency/run state (a failed run is never reused) and reopens the goal form
  pre-filled via `StudioGoalForm initialProfile={submittedProfile}`.

### 2.3 `apps/web/src/components/studio/StudioJobProgress.tsx`
* Added the `onEditRequest` action, rendered as "Edit your request" only when a submitted
  profile exists and the run is `failed`/`canceled`. "Create another roadmap" (blank) and
  "Retry generation" (recoverable/canceled only, calling the owned retry route) remain.

### 2.4 Tests
* `apps/web/src/lib/__tests__/studioGeneration.test.ts` (+2): `resumableJob` selects the newest
  in-flight generation (incl. `awaiting_input`/`cancel_requested`) and ignores terminal jobs
  and non-generation operations.
* `apps/web/src/components/studio/__tests__/StudioRoadmapGenerator.test.tsx` (+3): resumes the
  owned in-flight generation on a fresh mount without creating a new job; does not resume
  terminal/refinement jobs; reopens the goal form pre-filled when editing a failed request.

No backend runtime change was required; the existing owner-scoped job routes and lease fencing
already implement cancellation/stale-publish safety and explicit retry (see §3.3).

The already-passing repository tests cover the server side of this ticket:
* `test_cancel_and_late_checkpoint_are_fenced` — a late worker result after cancel is rejected
  (`StaleLeaseError`), so a canceled run cannot publish.
* `test_saved_usage_limits_and_receipts_survive_retry` / `test_exhaustion_requires_new_run` —
  retry re-queues a recoverable/canceled run and preserves budget; a non-recoverable failure
  raises (`NOT_RECOVERABLE`).
* `test_owner_lifecycle_and_references` — cancel → read → list returns the owned job (the
  "refresh resumes owned job" server contract), plus `test_other_owner_cannot_access_job`

## 4. Acceptance-Criteria Mapping

| Acceptance criterion | Evidence |
| :--- | :--- |
| Refresh resumes owned job | `resumableJob` + mount effect in `StudioRoadmapGenerator`; test "resumes the owned in-flight generation on a fresh mount" (progress shown, no duplicate `create`/`start`). Server contract: `GET /roadmap/jobs` (existing owner-scoped list). |
| Cancellation/stale attempts cannot publish | Existing `test_cancel_and_late_checkpoint_are_fenced` (stale checkpoint/lease after cancel is rejected) and lease-guarded `publish`; no client path publishes. |
| Retry semantics are explicit | `StudioJobProgress` shows "Retry generation" only for `error.recoverable`/`canceled` and surfaces the server `NOT_RECOVERABLE`/`INVALID_STATE` error; "Create another roadmap"/"Edit your request" reset run state for a non-recoverable failure. Server rules in `JobRepository.retry` (existing tests). |
| Failed profile remains editable | "Edit your request" reopens the goal form with `initialProfile={submittedProfile}`; test "reopens the goal form pre-filled when editing a failed request". |
| Out of scope honored (no local timers, no job-system replacement) | The flow continues to project server snapshots/events only; `resumableJob` reads the real job list. |

## 5. Limitations

* Auto-resume is scoped to the gated studio generator route; surfacing resume affordances on
  public entry points is later ticket scope.
* A resumed run intentionally does not auto-navigate on completion; the learner uses
  "Open your roadmap".
