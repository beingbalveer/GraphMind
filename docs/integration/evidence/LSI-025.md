## 1. Executive Summary & Objective

In accordance with [LSI-025](file:///Users/balveer/Projects/GraphMind/docs/integration/LEARNING_STUDIO_BACKLOG.md#lsi-025-public-snapshot-model-and-publication), this change adds **immutable public snapshot storage** and **controlled publication** from validated private curriculum output. It implements the public contracts frozen in [LSI-002 §3](./LSI-002.md#3-public-domain-contracts-guest--discovery) (catalog list, versioned roadmap detail, lesson body) and the identity model in LSI-002 §2 (`Public Template` = `templateId`; `Public Snapshot` = `templateId + snapshotVersion`).

Rather than a CMS/admin product, publication is **curated seed/publish tooling**: a curator calls `PublicSnapshotService.publish_revision` (or the batch helper `seed_public_snapshots`) with a validated revision and a strict `PublicSnapshotPublication` input. The service projects the private curriculum into a separate, normalized, frozen public schema.

The design is deliberately decoupled from the private curriculum tables:

1. **Immutable, versioned storage.** Public content lives in dedicated tables (`public_snapshots`, `..._phases`, `..._topics`, `..._sources`, `..._topic_sources`). A single private-provenance table (`public_snapshot_origins`) is the only place private IDs live, and its foreign keys are `ON DELETE SET NULL`, so a published snapshot survives unpublishing and deletion of the private copy it was curated from.
2. **Deterministic, opaque public identities.** Public topic/phase/source IDs are `uuid5`-derived (`pub_topic_`, `pub_phase_`, `pub_src_`) from the private ID and `template_id`, so they are stable across versions yet reveal nothing about private IDs. Private prerequisites are remapped to public topic IDs.
3. **Vetted content only.** `sanitize_curriculum` rejects ambiguous structure (`SNAPSHOT_UNSTRUCTURED`) and drops archived/non-active items, unvetted (`unavailable`) and unreferenced sources, and all source provenance/evidence/access/reference metadata.
4. **Atomic freeze + immutability.** Publication writes one snapshot in a single transaction; the `(template_id, snapshot_version)` unique constraint makes a concurrent duplicate fail atomically. A `content_hash` over the canonical sanitized payload makes an identical re-publish an idempotent no-op and rejects changed content under the same version with `SNAPSHOT_IMMUTABLE`.
5. **Unpublish stops reads without deleting data.** Unpublishing flips a status flag; every public read filters `status = 'published'`. Frozen rows and the private copy are untouched, and the action is permission-gated and idempotent.

## 2. Changes Made

### 2.1 Public DTOs and publication input (`apps/api/src/schemas/public.py`) — NEW
* Public read models matching LSI-002 §3: `PublicRoadmapSummary`, `PublicRoadmapSummaryList`, `PublicRoadmapDetail`, `PublicPhaseDetail`, `PublicTopicSummary`, `PublicLessonDetail`, `PublicSourceReference`, plus the tooling result `PublicSnapshotRecord` (`snapshot_version` maps to `PublicSnapshotRecord.snapshot_version`).
* Strict publication input `PublicSnapshotPublication` (Pydantic v2 via `CurriculumSchema` → `extra="forbid"`), with a `template_id` pattern (`^[a-z0-9][a-z0-9-]{0,63}$`), a `snapshot_version` pattern, and validators for slug shape, bounded tags, outcomes and prerequisites. Values not supplied (level, study weeks, hours/week, summary) are derived from the validated private profile.
* `PublicLessonDetail.content_markdown` is `str | None` to represent the honest "not yet generated" state required by LSI-008 (the LSI-002 draft showed a required field).

### 2.2 Immutable ORM storage (`apps/api/src/models/public_snapshot.py`) — NEW
* `PublicSnapshot`, `PublicSnapshotPhase`, `PublicSnapshotTopic`, `PublicSnapshotSource`, `PublicSnapshotTopicSource` hold only vetted lesson/reference data.
* `PublicSnapshotOrigin` is the sole private-provenance table (`source_workspace_id`, `source_roadmap_id`, `source_revision_id`, `published_by`), never read by DTO builders; all private FKs are `ON DELETE SET NULL`.
* Constraints/checks mirror the migration: status/level/path/format enums, week/hour bounds, `topic_count > 0`, per-snapshot unique topic slug, and lookup indexes.

### 2.3 Publication service (`apps/api/src/services/roadmap/public_snapshots.py`) — NEW
* `PublicSnapshotError(code, message, detail)` with stable public-safe codes: `PUBLICATION_FORBIDDEN`, `SNAPSHOT_UNVALIDATED`, `SNAPSHOT_UNSTRUCTURED`, `SNAPSHOT_EMPTY`, `SNAPSHOT_METADATA_INCOMPLETE`, `SNAPSHOT_IMMUTABLE`, `SNAPSHOT_SLUG_CONFLICT`, `SNAPSHOT_NOT_FOUND`, `ROADMAP_NOT_FOUND`, `REVISION_NOT_FOUND`.
* `PublicSnapshotService.publish_revision(actor, publication, workspace_id, revision_id)` — permission, validation, sanitization, content-hash immutability, atomic insert of the whole snapshot.
* `PublicSnapshotService.unpublish(actor, template_id, snapshot_version)` — permission-gated, idempotent status flip.
* Minimal reads to prove the unpublish boundary: `read_roadmap`, `read_lesson`, `list_published` (HTTP surfaces are LSI-026/LSI-027 scope).
* `sanitize_curriculum(view, template_id, publication)` and `_content_hash(snapshot)`.
* `CuratedSnapshotSeed` + `seed_public_snapshots(session, actor_id, seeds)` batch tooling.

### 2.4 Model registry (`apps/api/src/models/__init__.py`)
* Exports the six new models (and adds them to `__all__`) so `Base.metadata` and Alembic autogenerate see the tables.

### 2.5 Migration (`apps/api/alembic/versions/20261015_0007_add_public_snapshots.py`) — NEW, only new migration
* `revision = "20261015_0007"`, `down_revision = "20261015_0006"` (single linear head).
* Creates all six tables with FKs/unique/check constraints and indexes; idempotent (no-op when fully present; raises on a partially-initialized schema); fully reversible via `downgrade()`.

### 2.6 Focused tests — NEW
* `apps/api/tests/roadmap/test_public_snapshots.py` — 16 tests: freezing/stable public IDs, idempotent re-publish, immutability under drift, unpublish (reads stop, private copy survives), permission checks, unvalidated rejection, sanitization/privacy (including a pure sanitizer unit test), unstructured rejection, strict input bounds, seed batch, slug semantics, and survival of private deletion.
* `apps/api/tests/test_public_snapshot_migration.py` — 2 tests: linear-head linkage and fresh migration round trip (complete, idempotent, reversible, stores/reads frozen rows).

## 4. Ticket Status Transition & Limitations

* **Transition:** `TODO` → `IN_PROGRESS` → `VERIFYING`. All scope and acceptance criteria are implemented and verified. Per the integrating session's instruction, this ticket did **not** run `git add`/`commit`/`push` and did **not** edit the shared backlog board (`docs/integration/LEARNING_STUDIO_BACKLOG.md`) or `HANDOFF.md`; the final `VERIFYING` → `DONE` transition and completion commit (with this evidence) are the integrating session's step.
* **Limitations / explicit boundaries:**
  * **`slug` semantics.** A slug identifies the roadmap *template* (LSI-002: `GET /public/roadmaps/{slug}` returns a `snapshot_version`), so every version of a template shares one slug while distinct templates must not. That cannot be expressed as a single-table unique constraint (a unique on `slug` would block new versions; a unique on `(template_id, slug)` would too), so cross-template slug uniqueness is enforced in the publication service and `slug` carries a non-unique lookup index. A concurrent race between two *distinct* templates publishing an identical curator-supplied slug is not DB-enforced; auto-derived slugs default to the already-unique `template_id`, so this only affects explicit slugs. `read_roadmap(slug=...)` resolves the newest published version deterministically.
  * **Allowlist not yet replaced.** `services/roadmap/generator_request.py`'s `CURATED_SAMPLE_TEMPLATES` allowlist (LSI-020) was intentionally left untouched because the ticket's file scope was limited to the public-snapshot model/service/schema/migration/tests. Wiring `sample_template_ref` resolution onto the published snapshot table belongs to LSI-022/LSI-026/LSI-027 and is the documented successor to this allowlist.
  * **HTTP APIs deferred.** The service exposes minimal reads (`read_roadmap`/`read_lesson`/`list_published`) only to prove the publish/unpublish boundary; the anonymous catalog and versioned lesson routes are LSI-026/LSI-027 scope.
  * **Test DB schema rebuild.** `apps/api/tests/conftest.py` builds the test schema with `Base.metadata.create_all`, which does not alter pre-existing tables. Because `slug`'s uniqueness shape changed while developing, the stale `public_snapshot*` tables were dropped once so they were recreated from the final metadata; the committed migration is the source of truth for real databases.
