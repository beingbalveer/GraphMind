## 1. Executive Summary & Objective

In accordance with [LSI-026](file:///Users/balveer/Projects/GraphMind/docs/integration/LEARNING_STUDIO_BACKLOG.md#lsi-026-public-catalog-api), this change exposes the **approved anonymous catalog contract** from [LSI-002 §3.1](./LSI-002.md#31-public-catalog-list) over the immutable public snapshots frozen in LSI-025:

* `GET /api/v1/public/roadmaps` — searchable, category/level-filtered, paginated list of published roadmap templates, returning the frozen `PublicRoadmapSummaryList` DTO.

The route is **read-only and anonymous**: it requires no authentication token and no workspace header, and it depends only on the request-scoped database session. All catalog reads flow through `PublicSnapshotService` from LSI-025, so private workspace/roadmap/revision/chat/user identity can never cross the boundary.

Design decisions:

1. **One card per template.** LSI-025 allows multiple published versions of one template (`uq_public_snapshot_version` on `(template_id, snapshot_version)`), and `PublicRoadmapSummary.id` is the `template_id`. Listing every published row would therefore emit duplicate card ids. The catalog ranks published rows per template and keeps the **newest published version** (`published_at` then `id`), the same deterministic choice `read_roadmap` uses when resolving a template's newest version by `slug`. Unpublishing the newest version makes the catalog fall back to the last still-published version.
2. **Published only.** Every query is anchored on `status = 'published'`; an unpublished or superseded snapshot can never appear.
3. **Bounded and deterministic.** `limit` (1–100), `offset` (≥ 0), and free-text lengths are validated by FastAPI; invalid input fails with the repository's structured `VALIDATION_ERROR` payload. Ordering has an `id` tie-break, and empty scrolls echo back the requested `limit`/`offset` with `total = 0`.
4. **Literal search.** Search matches the roadmap title or summary case-insensitively, with LIKE metacharacters (`%`, `_`, `\`) escaped so a user query is never expanded into a wildcard match.
5. **No new indexes needed.** The LSI-025 migration (`20261015_0007`) already ships `idx_public_snapshot_catalog` on `(status, category, level)` plus per-column indexes; per the ticket, no new migration was added. A focused test pins the catalog index shape.

## 2. Changes Made

### 2.1 Anonymous catalog router (`apps/api/src/routers/public_catalog.py`) — NEW
* `APIRouter(prefix="/public/roadmaps", tags=["Public Catalog"])` with `GET ""` → full path `GET /api/v1/public/roadmaps`.
* Query parameters per LSI-002 §3.1: `query` (≤ 200 chars), `category` (1–64 chars), `level` (`PublicLevel` literal), `limit` (default 20, 1–100), `offset` (≥ 0).
* No auth dependency; only `get_db`. Response model is the strict `PublicRoadmapSummaryList` (`extra="forbid"`, camelCase aliases).
* Delegates to `PublicSnapshotService.list_catalog`; contains no business logic beyond parameter bounds.

### 2.2 Catalog projection (`apps/api/src/services/roadmap/public_snapshots.py`)
* Added `PublicSnapshotService.list_catalog(...)`: returns one `PublicRoadmapSummary` per template for its newest published version, with a correct `total` and SQL-side `limit`/`offset` (window function `row_number()` partitioned by `template_id`). Reuses the existing `_summary` DTO builder.
* Added module helper `_contains_pattern(value)`: escapes `\`, `%`, `_` and builds a literal `%value%` pattern used with `ilike(..., escape="\\")`.
* `list_published` (LSI-025) was left unchanged so the LSI-025 read boundary and its tests are unaffected.

### 2.3 Router registration (`apps/api/src/main.py`)
* Added `public_catalog` to the `from routers import (...)` block.
* Registered `app.include_router(public_catalog.router, prefix="/api/v1")` after `files.router`.
* Registration is additive and does not disturb the concurrent LSI-027 `public_snapshots` router; the two own disjoint paths (see §3.4).

### 2.4 Focused tests (`apps/api/tests/roadmap/test_public_catalog.py`) — NEW
* 9 tests: anonymous published-only listing + camelCase DTO shape, literal title/summary search (incl. `%` escaping), category/level filters, bounded deterministic pagination, newest-version-only (with unpublished fallback), deterministic empty results, invalid-filter rejection, private-metadata scan, and the catalog index shape.

## 4. Ticket Status Transition & Limitations

* **Transition:** `TODO` → `IN_PROGRESS` → `VERIFYING`. All scope and acceptance criteria are implemented and verified. Per the integrating session's instruction, this ticket did **not** run `git add`/`commit`/`push` and did **not** edit the shared backlog board (`docs/integration/LEARNING_STUDIO_BACKLOG.md`) or `HANDOFF.md`; the final `VERIFYING` → `DONE` transition and completion commit (with this evidence) are the integrating session's step.
* **Limitations / explicit boundaries:**
  * **Newest-version dedup is a deliberate catalog decision.** The catalog returns one card per template (newest published version) rather than every published row, because `PublicRoadmapSummary.id` is the template id and duplicate cards would be invalid. `PublicSnapshotService.list_published` (LSI-025) is untouched; `list_catalog` is the catalog-facing projection. Full version history is LSI-027's versioned read (`?version=`), not the catalog.
  * **Search scope.** Search matches `title` and `summary` only (case-insensitive, literal). Category and level are exact-match filters; tag search is out of scope for this ticket.
  * **No new migration/index.** The ticket scope mentions indexes; these already exist from LSI-025, and the task explicitly forbade new migrations, so only verification (not creation) is delivered here.
  * **Concurrency with LSI-027.** This router was created in a new file (`routers/public_catalog.py`) per instruction; the LSI-027 router (`routers/public_snapshots.py`) was left untouched. `main.py` now registers both, and the OpenAPI check (§3.4) confirms the three public paths do not collide. The `git status` working tree also contains in-flight LSI-022/LSI-027 and web changes from other agents; none were modified by this ticket.
  * **Signed-in collection/enrollment routes are out of scope** (LSI-028/LSI-029/LSI-031).
