# LSI-028: Transactional Save-Copy Service

**Ticket:** LSI-028
**Epic:** D (Public immutable learning)
**Type:** Backend
**Priority:** P0
**Status:** DONE
**Dependencies:** LSI-005 (DONE), LSI-025 (DONE), LSI-027 (DONE)

**Baseline Git Commit:** `000521c`

---

## 1. Objective

Implement the signed-in half of the LSI-002 §4 boundary: a learner saves one
*published* public snapshot into an authorized workspace and receives a fully
independent private copy. The copy must own fresh private curriculum/revision/topic
identities, persist a durable public-topic → private-topic map, be idempotent per
`(workspace, template)`, never mutate the frozen public snapshot, and be written
atomically so a failure leaves no orphan anchor, roadmap, or copy.

---

## 2. Design Decisions (confirmed with the user, 2026-10-16)

* **Hosting:** the copy's roadmap/curriculum lives in the given `{workspace_id}`;
  the client creates the (empty) workspace as part of its save flow (LSI-031).
  Dedupe key is `(workspace_id, template_id)`: re-saving the same template returns
  the existing copy (`200`); a workspace that already hosts a *different* roadmap is
  a `409`.
* **`sourceSnapshotRef` format:** `template_id:snapshot_version`
  (e.g. `roadmap-python-backend:2026-10-14.1`), stored on the private profile and the
  protected anchor metadata.

## 3. Changes Made

### 3.1 New tables — `apps/api/src/models/public_snapshot_copy.py`
* `public_snapshot_copies` — the private enrollment identity. Binds one workspace to
  one `template_id`/`snapshot_version` and to the produced `roadmap_id`/`revision_id`.
  `uq_copy_workspace_template` = durable idempotency; `uq_copy_workspace_key` rejects a
  reused `Idempotency-Key` for a different template; `uq_copy_roadmap` keeps one copy
  per roadmap; `idx_copy_template_version` supports template lookups.
* `public_snapshot_copy_topics` — durable `public_topic_id → private_topic_id` map
  (composite PK `(copy_id, public_topic_id)`, FK to `curriculum_items`), so later intent
  resumption (LSI-031/LSI-032) never relies on ID equality.
* Registered both models in `apps/api/src/models/__init__.py`.

### 3.2 Migration — `apps/api/alembic/versions/20261016_0008_add_public_snapshot_copies.py`
* `down_revision = 20261015_0007` (single linear head). Idempotent/partial-schema guard
  mirrors the LSI-025 migration: re-running is a no-op; a partially present schema raises.

### 3.3 DTOs — `apps/api/src/schemas/enrollment.py`
* `SaveRoadmapCopyRequest` (`template_id`, `snapshot_version`, `custom_title`),
  `EnrollmentTopicMap`, `EnrollmentDetail` (private IDs, `source_snapshot_ref`,
  `topic_progress`, and the durable `topic_map`). Private-boundary only; never served
  anonymously.
* Added the optional, additive `source_snapshot_ref` field to `LearningProfile`
  (`apps/api/src/schemas/curriculum.py`).

### 3.4 Service — `apps/api/src/services/roadmap/save_copy.py`
* `SaveCopyService.save` owns **no commit** (the route transaction makes the whole copy
  atomic). It locks the workspace (`SELECT ... FOR UPDATE`) to serialize concurrent saves,
  then: returns the existing copy when `(workspace, template)` is already present;
  rejects non-`published`/unknown versions (`SNAPSHOT_OBSOLETE`, 400); rejects a reused key
  for a different template (`IDEMPOTENCY_MISMATCH`, 409); rejects a workspace already
  hosting a different roadmap (`WORKSPACE_HAS_ROADMAP`, 409).
* Projects the frozen public rows into a fresh, valid private curriculum: deterministic
  private IDs via `uuid5` scoped to `workspace:template:version:public_id`, so every copy
  is independent of every other copy and of the public identity. Re-validates with the
  shared `validate_curriculum` and returns `SNAPSHOT_NOT_COPYABLE` (409) if the frozen
  content cannot be copied. Returns `(detail, created)` → `201` on create, `200` on reuse.
* `_existing_detail` reconstructs the same private detail (via `CurriculumRepository`),
  so a retry is byte-for-byte stable and creates no duplicate rows/anchor.

### 3.5 Route — `apps/api/src/routers/workspaces.py`
* `POST /api/v1/workspaces/{workspace_id}/learning-roadmaps` with mandatory
  `Idempotency-Key` header; `require_roadmap_write` + `get_roadmap_user` authorization;
  structured `SaveCopyError` → `RoadmapHTTPError`/`JobError` mapping; `201`/`200` chosen by
  whether the copy was created or reused.

### 3.6 Tests
* `apps/api/tests/roadmap/test_save_copy.py` (14): private identity + valid
  relationships, custom title, retry idempotency (no duplicates), reused-key conflict,
  workspace-already-hosts conflict, two-workspace isolation, outsider `404` / viewer `403`,
  editor member maps to the workspace owner, mandatory idempotency key `422`,
  obsolete/unknown/withdrawn snapshot `400`, public snapshot unchanged, and atomic
  rollback with no orphans.
* `apps/api/tests/test_public_snapshot_copy_migration.py` (2): linear-head link and a
  fresh, idempotent, reversible migration round trip with constraints/indexes/row FKs.

## 5. Acceptance-Criteria Mapping

| Acceptance criterion | Evidence |
| :--- | :--- |
| New copy gets private IDs | `_build` namespaces `uuid5` by `workspace:template:version:public_id`; test asserts `item_*` private topic IDs and that they differ from `pub_topic_*`. |
| Relationships are valid | `validate_curriculum` re-runs on the projection; test asserts root→phase→topic containment + a preserved prerequisite edge, and that every resource resolves to a private source. |
| Retry creates no duplicate | `test_retry_returns_the_existing_copy_without_duplicates` — second save `200`, same roadmap/revision/topic map; exactly 1 roadmap, 1 copy, 1 anchor. |
| Copies are independent | `test_two_workspaces_receive_isolated_copies` — disjoint private topic IDs across two workspaces in two workspaces. |
| Rollback leaves no orphan workspace/anchor | `test_failed_copy_rolls_back_without_orphans` — a forced mid-copy failure returns `500` and leaves 0 copies, 0 roadmaps, 0 nodes. |
| Idempotency / concurrency | `uq_copy_workspace_template` + `uq_copy_workspace_key` + workspace `FOR UPDATE` lock; reused-key-different-template → `IDEMPOTENCY_MISMATCH` (`409`). |
| Member mapping | `test_editor_member_saves_into_the_owners_workspace` — an editor saves; the roadmap belongs to the workspace owner. |
| Source unchanged | `test_saving_a_copy_never_mutates_the_public_snapshot` — status/hash/topic counts and source counts are identical before and after a save. |
| Obsolete/unknown/unpublished fails honestly | `test_obsolete_or_unknown_snapshot_is_rejected` — all three collapse to `SNAPSHOT_OBSOLETE` (`400`). |
| Out of scope honored (no public mutation, no blind endpoint adoption) | Copy tables are separate from public snapshots; the route follows the LSI-002 §4.1 endpoint contract. |

## 6. Limitations

* The client creates the empty target workspace (LSI-031 save flow); this service assumes
  an existing, authorized workspace and only fails with `WORKSPACE_NOT_FOUND` otherwise.
* `SNAPSHOT_NOT_COPYABLE` (409) is a defensive path: `PublicSnapshotService.publish_revision`
  already drops invalid topics, but a manually edited snapshot could still be uncopyable.
* Idempotency is durable per `(workspace, template)`; the request `Idempotency-Key` is an
  additional guard against a key being reused for a different template, not the dedupe key.
