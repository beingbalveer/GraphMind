## 1. Objective

Give guests (and signed-in visitors alike) a real, anonymous public learning
catalog. LSI-026 shipped the frozen `GET /api/v1/public/roadmaps` contract but the
only public URL helper (`buildPublicCatalogUrl`) returned `/learn` for a route
that did not exist, and the Studio "Browse" tab toggled a nav state with no
rendering branch. LSI-029 wires that real discovery surface: search, level and
category filters, pagination, honest loading/empty/no-results/error states, and
public-card navigation — while proving the public page never issues a private
fetch.

---

## 2. Design Decisions

* **Anonymous by construction.** The page's only network dependency is the
  LSI-026 public catalog endpoint. No workspace/curriculum/progress call is made,
  so a guest without a session can read the catalog and there is nothing to
  authorize. This is asserted directly in tests (every `fetch` URL must contain
  `/public/`).
* **One typed client, one data hook, one presentational view.** `publicCatalogApi`
  owns the contract, `usePublicCatalog` owns fetching/filters/pagination/retry,
  and `StudioCatalogView` is a pure prop-driven view. This mirrors the existing
  `StudioHomeView`/`StudioMyLearningView` split and keeps the view trivially
  testable.
* **No fixture catalog.** Out-of-scope "prototype fixture catalog" is honored: the
  Studio Browse affordance navigates to the real `/learn` page rather than
  rendering demo cards.
* **Filters, not identity, in the query string.** `buildPublicCatalogUrl` carries
  optional `query`/`category`/`level` filters. Purely filter state, so a query
  string is correct here — the URL contract's "no primary IDs in query params"
  rule only governs `workspaceId`/`chatId`.
* **Public header drops private nav.** `StudioHeader` gained an opt-in
  `showNav?: boolean` (default `true`) so the anonymous `/learn` surface does not
  present signed-in Studio destinations (Home / My Learning / Create) to a guest.

## 3. Changes Made

### 3.1 Public URL helper — `apps/web/src/lib/urls.ts`
* `buildPublicCatalogUrl(params?)` now accepts optional `query`/`category`/`level`
  and encodes them into `/learn?…`; the no-arg call still returns `/learn`
  unchanged. Implementation stays dependency-free so the middleware bundle is
  unaffected.

### 3.2 Typed catalog client — `apps/web/src/lib/publicCatalogApi.ts` (new)
* `PublicRoadmapSummary` / `PublicRoadmapSummaryList` mirror the server's
  camelCase aliases; `PublicRoadmapLevel` + `isPublicRoadmapLevel` guard level
  values.
* `buildPublicCatalogQuery` produces a deterministic, encoded query string and
  omits blank filters entirely.
* `listPublicRoadmaps(params, signal)` performs the anonymous
  `GET /api/v1/public/roadmaps` read through `apiFetch` and forwards an
  `AbortSignal`.

### 3.3 Catalog data hook — `apps/web/src/hooks/usePublicCatalog.ts` (new)
* Owns items/total/page/pageCount/isLoading/error, plus `setQuery`, `setCategory`,
  `setLevel`, `setPage`, `resetFilters`, and `retry`.
* Debounces the free-text filter (`PUBLIC_CATALOG_SEARCH_DEBOUNCE_MS = 300`),
  resets to page 1 on every filter change, aborts superseded requests (so no stale
  response overwrites a newer one), and accumulates discovered categories (so a
  learner can switch categories after narrowing).
* Maps failures to an actionable message (`5xx` → "temporarily unavailable"),
  distinguishing "could not load" from "nothing published".

### 3.4 Presentational view — `apps/web/src/components/studio/StudioCatalogView.tsx` (new)
* Search `Input`, level and category `SegmentedTabs`, a responsive card grid, and
  Prev/Next pagination — all built from `@/components/ui` primitives with semantic
  tokens (`bg-surface`, `border-border-subtle`, `text-foreground-muted`,
  `rounded-2xl`) and the standard typography scale.
* Distinct, honest states: loading skeleton, error banner + Retry, empty catalog,
  no-results with "Clear search and filters", and pagination controls only when
  `pageCount > 1`.

### 3.5 Public route — `apps/web/src/app/learn/page.tsx` (new)
* Guest-readable `/learn` page: brand-only `StudioHeader` (`showNav={false}`) over
  `StudioCatalogView` fed by `usePublicCatalog`. Opening a card calls
  `buildPublicRoadmapUrl(slug)` and navigates to `/learn/{slug}` (the guest
  course/lesson surfaces arrive in LSI-030).

### 3.6 Studio Browse wiring — `apps/web/src/app/studio-preview/page.tsx`, `apps/web/src/components/studio/StudioHeader.tsx`
* `handleNavigate("browse")` and both `onBrowse` handlers now `router.push` the
  real public catalog instead of setting a rendering-less `activeNav` value; the
  dead `browse` branch is gone.
* `StudioHeader` gained `showNav?: boolean` (default `true`) for public surfaces.

### 3.7 Tests
* `apps/web/src/lib/__tests__/publicCatalogApi.test.ts` (5): query building /
  encoding, blank-filter omission, anonymous request shape (no `Authorization`),
  typed error surfacing, level guard.
* `apps/web/src/lib/__tests__/publicUrls.test.ts` (3): bare + filtered
  `buildPublicCatalogUrl`, and public roadmap/lesson deep links.
* `apps/web/src/hooks/__tests__/usePublicCatalog.test.tsx` (5): anonymous mount
  read, debounced search + page reset, level/category filters with category
  accumulation, typed failure + retry recovery, `resetFilters`.
* `apps/web/src/components/studio/__tests__/StudioCatalogView.test.tsx` (8):
  loading, error+retry, cards/`onOpen`, filter change callbacks, clearing filters
  via the All tabs, empty, no-results+clear, pagination.
* `apps/web/src/app/learn/__tests__/public-catalog-page.test.tsx` (4): renders from
  the public endpoint only (single request, no `/workspaces/`), card → canonical
  public URL navigation, brand-only header (no private nav), and retry recovery.

## 5. Acceptance-Criteria Mapping

| Acceptance criterion | Evidence |
| :--- | :--- |
| Guest and signed-in users see the same published catalog | `/learn` renders `GET /api/v1/public/roadmaps` only; the endpoint is anonymous, so no auth state is consulted (LSI-026 contract). |
| Loading / empty / retry states work | View tests cover the skeleton, empty catalog, no-results, and error+Retry; the page test proves a `503` recovers on Retry. |
| Root dashboard preserved | No change to `/` or its middleware protection; `/learn` was already an approved public prefix in LSI-004, and `/` stays a private redirect (unchanged `middleware.test.ts`). |
| No private fetch on the public page | Page test asserts exactly one request, containing `/api/v1/public/roadmaps` and never `/workspaces/`; `publicCatalogApi` has no private import. |
| Real Browse navigation and public URL helpers | Studio Browse (`handleNavigate`/`onBrowse`) opens the real `/learn`; `buildPublicCatalogUrl` supports filters; cards navigate via `buildPublicRoadmapUrl`. |
| Out of scope honored (no fixture catalog, no private copies) | Browse navigates to the real page; no demo cards or private-copy logic were added. |

## 6. Limitations

* Category facet options are discovered from loaded results (accumulated per
  session) because LSI-026 exposes no category-list endpoint. This is honest
  (no fixture) and only surfaces categories the visitor has actually seen; a
  future ticket can add a server-side facet list if needed.
* The catalog page does not yet write its filters back to the URL
  (`buildPublicCatalogUrl`'s filter params are supported and unit-tested but only
  the no-arg form is called today). Card navigation and the Browse affordance are
  fully wired.
* Cards link to `/learn/{slug}`, whose guest course/lesson/List/Canvas surfaces
  are the next ticket (LSI-030); until then a card link resolves to the LSI-030
  route when it lands.
