## 1. Objective

Complete the guest reading journey that LSI-029 started. LSI-026 shipped the
anonymous public catalog and LSI-027 froze the anonymous public roadmap/lesson
read boundary (`GET /api/v1/public/roadmaps/{slug}` and
`…/topics/{topicSlug}`), but the catalog's card links resolved to `/learn/{slug}`
routes that did not exist. LSI-030 adds those routes: a read-only course surface
that renders the frozen snapshot as an ordered **List** or the existing spatial
**Canvas**, and a read-only **lesson reader**. Both reuse the public ids from the
snapshot, mutate nothing private, and gate the one private affordance (saving /
tracking) behind sign-in.

---

## 2. Design Decisions

* **Anonymous by construction.** Both guest routes read only the LSI-027 public
  endpoints through `apiFetch`; no workspace, curriculum, progress, or
  canvas-layout call is issued. Tests assert every request URL contains
  `/public/` and never `/workspaces/`.
* **One read-only projection; two views.** `projectPublicRoadmap` projects the
  public DTO into the existing `CurriculumView` shape with `canWrite: false` and
  empty private ids (`workspaceId: ""`, `canvasAnchorChatId: ""`). List and Canvas
  therefore address the **same stable public ids** and share one source of truth;
  no second, divergent data model is introduced.
* **Reuse the real canvas, provably without a protected request.** Guest Canvas
  renders `RoadmapCanvas` with `readOnly`. Passing `undefined`
  workspace/anchor/chat makes `useCanvasLayout` skip the protected layout API
  entirely, so a guest canvas uses local, in-memory layout only (verified in
  `apps/web/src/lib/canvas/layoutPersistence.ts`). This honors the out-of-scope
  "no writes to private layout API" without a bespoke canvas.
* **Honest not-available state.** Missing, stale, superseded, and unpublished
  content all collapse to the same neutral `404` from LSI-027. The data hook maps
  that single `404` to a first-class `notFound` state; the views render an honest
  "this roadmap/lesson is not available" panel (never a mock or an empty shell).
* **Private actions are gated, not faked.** "Sign in to save this roadmap",
  "Sign in to track progress and ask the tutor" both navigate to
  `/login?next=<current path>` via the new `buildLoginUrl`. Nothing is written
  for a guest; the resumed intent itself is LSI-032's job.
* **No separate guest canvas route.** Consistent with the URL contract, Canvas is
  a local view toggle inside `/learn/{slug}` (`SegmentedTabs`: List ⇄ Canvas), not
  a new path segment. The canonical guest URLs remain
  `/learn`, `/learn/{slug}`, and `/learn/{slug}/lessons/{topicSlug}`.
* **Dependency-free lesson rendering.** `LessonMarkdown` formats only the
  constructs the curriculum generator emits (headings, fenced code, paragraphs)
  with semantic tokens; a guest never receives raw HTML.

## 3. Changes Made

### 3.1 Public snapshot client — `apps/web/src/lib/publicSnapshotApi.ts` (new)
* `PublicRoadmapDetail`, `PublicPhaseDetail`, `PublicTopicSummary`,
  `PublicLessonDetail`, and `PublicSourceReference` mirror the LSI-027 camelCase
  contract (stable `pub_topic_…` / `pub_phase_…` / `pub_src_…` ids).
* `readPublicRoadmap(slug, signal)` and `readPublicLesson(slug, topicSlug, signal)`
  perform the anonymous reads through `apiFetch`, forwarding an `AbortSignal`.
  Calls only `/public/…`; no private identity is requested or returned.

### 3.2 Read-only projection — `apps/web/src/lib/publicCurriculum.ts` (new)
* `publicTopicSequence(detail)` yields the whole-roadmap reading order (phase
  order, then topic order) with phase labels for lesson navigation.
* `projectPublicRoadmap(detail)` builds a `CurriculumView` with a synthetic
  `pub-root` container, containment edges (root→phase→topic), preserved
  prerequisite edges between public topics, sources, and computed core minutes.
  It always sets `canWrite: false`, empty private workspace/anchor ids, and empty
  progress, so no private state can leak into or be read from a guest view.

### 3.3 Route-param helper — `apps/web/src/lib/routeParams.ts` (new)
* `firstParam(value)` decodes a single (possibly array) App Router param,
  tolerating Next.js's param shapes.

### 3.4 Public data hook — `apps/web/src/hooks/usePublicSnapshot.ts` (new)
* `usePublicRoadmap(slug)` / `usePublicLesson(slug, topicSlug)` own
  data/isLoading/notFound/error/retry, abort superseded requests, map the neutral
  `404` to `notFound`, and surface an actionable error for other failures. No
  fetch occurs without a slug.

### 3.5 Guest views
* `apps/web/src/components/studio/PublicCourseView.tsx` (new): header (level /
  category / snapshot version / phases / lessons / approx hours), outcomes,
  `SegmentedTabs` **List ⇄ Canvas** toggle, ordered phase outline
  (`public-course-outline`) with `onOpenTopic(slug)`, the reused read-only
  `RoadmapCanvas`, verified sources, and the sign-in-gated save action. Distinct
  loading / not-available / error+Retry states.
* `apps/web/src/components/studio/PublicLessonReader.tsx` (new): back affordance,
  phase label, position (`Lesson i of n`), format/minutes badges, objectives,
  authored body (or an honest "not published yet" panel when the snapshot has no
  body), practice prompt, verified sources, sign-in-gated progress/tutor action,
  and previous/next lesson navigation (disabled at the ends).
* `apps/web/src/components/studio/LessonMarkdown.tsx` (new): narrow, dependency-
  free lesson-body renderer using the standard typography scale and tokens.

### 3.6 Guest routes
* `apps/web/src/app/learn/[slug]/page.tsx` (new): `/learn/{slug}` guest course
  page. Brand-only `StudioHeader` (`showNav={false}`), `PublicCourseView` fed by
  `usePublicRoadmap`; opening a topic navigates to the canonical lesson URL and
  the gated save action goes to `buildLoginUrl(pathname)`.
* `apps/web/src/app/learn/[slug]/lessons/[topicSlug]/page.tsx` (new):
  `/learn/{slug}/lessons/{topicSlug}` guest lesson reader. Fetches the public
  lesson plus the public roadmap (for phase label and prev/next), resolves the
  current position, and routes navigation through `buildPublicRoadmapUrl` /
  `buildPublicLessonUrl` and the gated action through `buildLoginUrl`.

### 3.7 URL helper — `apps/web/src/lib/urls.ts`
* Added `buildLoginUrl(next?)` → `/login?next=<encoded>`; the `next` value is
  always encoded. No existing helper changed.

## 5. Acceptance-Criteria Mapping

| Acceptance criterion | Evidence |
| :--- | :--- |
| Published lessons readable | `/learn/{slug}/lessons/{topicSlug}` renders the authored body, objectives, practice, and sources from the public endpoint (reader + page tests). |
| List/Canvas use the same public IDs | Both modes project the same `projectPublicRoadmap` view; tests assert stable `pub_topic_…` ids and that the read-only canvas maps a clicked public topic id back to its slug. |
| No private mutation or protected-layout request | Page tests assert exactly the `/public/…` requests and never `/workspaces/`; the canvas is `readOnly` with empty workspace/anchor so `useCanvasLayout` issues no layout request; the projection is `canWrite:false`; the only private affordance routes to sign-in. |
| Unpublish fails honestly | The data hook maps the neutral `404` to `notFound`; the views render an explicit "not available" panel (roadmap + lesson) with no mock content. |
| Guest layout stays local per public snapshot | Canvas uses in-memory layout only (no persisted layout read/write) because no workspace/anchor identity is passed. |
| Private actions gated | Save and progress/tutor actions call `buildLoginUrl(pathname)`; tests confirm a guest click navigates to sign-in and performs no private write. |
| Mobile reading | Reader/course views use responsive `max-w-*`, `md:` paddings, and a single-column lesson body; the outline and canvas stack cleanly on narrow viewports. |
| Out of scope honored (no guest progress/chat/private layout writes) | No progress write, tutoring call, or layout mutation is implemented; those paths are gated to sign-in. |

## 6. Limitations

* Guest Canvas is a local view toggle inside `/learn/{slug}` rather than its own
  `/learn/{slug}/canvas` route, per the URL contract's "view mode is a path
  segment" rule being satisfied by the existing `/learn` prefix; the canvas state
  is in-memory only for guests (nothing is persisted), which is the intended
  read-only behavior.
* The gated sign-in actions preserve the current path via `buildLoginUrl`, but the
  resumed save/complete/tutor intent after login is the scope of LSI-032; LSI-030
  only routes a guest to sign-in and never trusts a callback payload.
* Lesson body rendering covers only the constructs the curriculum generator emits
  (headings, fenced code, paragraphs); richer markdown (tables, nested lists) is
  intentionally out of scope until a lesson needs it.
