## 1. Objective

Close the signed-in half of the guest→learner journey. LSI-030 made a published
snapshot readable to a guest and gated "save" behind sign-in; LSI-028 shipped the
transactional, idempotent save-copy service. LSI-031 wires the client: a
signed-in learner saves an independent private copy of the roadmap they are
reading, a duplicate click or a retry returns the **same** copy, the topic they
were on is preserved through the copied `topic_map`, and the learning collection
refreshes so the new copy appears. No public snapshot is ever mutated.

---

## 2. Design Decisions

* **The copy is already idempotent server-side; the client must not defeat it.**
  The route dedupes on `(workspace, template)`. The client therefore reuses the
  workspace that already hosts the snapshot rather than creating a second one, and
  holds one `Idempotency-Key` per `template:version` so a retry replays the same
  request. A duplicate click while a save is in flight returns the same pending
  promise instead of issuing a second write.
* **Fail safe on an unreadable collection.** Deciding "is it already saved?" from
  a list that swallows errors would misread "could not load" as "nothing saved"
  and create a duplicate copy. `listWorkspaces` (new) rejects on failure, and the
  save aborts retryably instead of writing.
* **One workspace per copy; two templates stay isolated.** When a snapshot is not
  yet saved, the client creates a fresh, empty workspace for the copy (per the
  LSI-028 design note). Saving a different template creates a different
  workspace, so two copies never share a roadmap workspace. A workspace this hook
  created is tracked per snapshot so a retry after a failed save never leaves an
  orphan workspace behind.
* **The mapped topic is data, not a query param.** The returned `topic_map`
  translates the guest's public topic to the private copy's topic id
  (`mapPublicTopicToPrivate`). Primary identities never enter a URL query string,
  honoring the URL contract; the private course is addressed by
  `buildWorkspaceUrl(workspaceId)`.
* **Collection refresh without a global store.** A successful save announces one
  `graphmind:learning-collection-changed` event; `useAuthorizedCurricula`
  subscribes and refreshes. This keeps the collection owner responsible for its
  own reload while letting a save anywhere trigger it. It is SSR-safe (guarded
  `window` access).
* **Backend unchanged.** LSI-028 already owns the atomic, idempotent, isolated
  copy service; LSI-031 is the client contract and UI, so no backend runtime
  change was needed.

## 3. Changes Made

### 3.1 Enrollment client — `apps/web/src/lib/enrollmentApi.ts` (new)
* `SaveRoadmapCopyRequest` (`templateId`, `snapshotVersion`, `customTitle`),
  `EnrollmentTopicMap`, `EnrollmentDetail` mirror the LSI-028 camelCase contract.
* `sourceSnapshotRef(templateId, snapshotVersion)` — the frozen
  `template_id:snapshot_version` identity shared with the server.
* `findSavedWorkspace(workspaces, templateId, snapshotVersion)` — locates the
  workspace already hosting the snapshot (by `curriculum.sourceSnapshotRef`).
* `mapPublicTopicToPrivate(enrollment, publicTopicId)` — resolves the private
  topic the guest's public topic was copied to.
* `saveRoadmapCopy(workspaceId, request, idempotencyKey)` — `POST
  /workspaces/{id}/learning-roadmaps` with the mandatory `Idempotency-Key`.
* `announceLearningCollectionChanged()` / `subscribeLearningCollectionChanged()` —
  the SSR-safe collection-change broadcast.

### 3.2 Strict collection list — `apps/web/src/lib/workspaceApi.ts`
* Added `listWorkspaces(signal?)`, which rejects on failure (unlike the
  error-swallowing `fetchWorkspaces`), so the save flow can distinguish
  "unreadable" from "empty".

### 3.3 Save hook — `apps/web/src/hooks/useSaveRoadmapCopy.ts` (new)
* Owns `status` (`idle`/`pending`/`saved`/`error`), `error`, `enrollment`,
  `created` (created vs reused), and `privateTopicId`, plus `save`, `retry`, and
  `reset`.
* Reuses an existing (or previously created) workspace, otherwise creates a fresh
  one; posts with one stable UUID idempotency key per `template:version`; guards
  duplicate clicks with a pending promise; announces the collection change on
  success.

### 3.4 Collection refresh — `apps/web/src/components/studio/useAuthorizedCurricula.ts`
* Subscribes to the collection-change event and refreshes, so a save updates the
  learner's collection without a reload.

### 3.5 Save UI — `apps/web/src/components/studio/PublicCourseView.tsx`
* New props (`isAuthenticated`, `saveStatus`, `saveError`, `savedCreated`,
  `onSave`, `onRetrySave`, `onOpenSavedCopy`). A guest keeps the LSI-030
  "Sign in to save this roadmap" gate; a signed-in learner sees "Add to my
  learning" → pending "Saving…" → "Saved to your learning" /
  "Already in your learning" with "Open my copy" → error + "Retry save".

### 3.6 Course page wiring — `apps/web/src/app/learn/[slug]/page.tsx`
* Reads `useAuth()` and `useSaveRoadmapCopy()`; a signed-in save uses the public
  roadmap's `id`/`snapshotVersion`/`title`, and "Open my copy" routes to
  `buildWorkspaceUrl(enrollment.workspaceId)`. A guest still routes to
  `buildLoginUrl(pathname)`.

## 5. Acceptance-Criteria Mapping

| Acceptance criterion | Evidence |
| :--- | :--- |
| Duplicate click returns the same copy | The hook's pending guard collapses a second click into the in-flight promise (test: one POST while pending); the backend additionally dedupes on `(workspace, template)`. |
| Retry returns the same copy | Retry replays with the same idempotency key and reuses the tracked workspace (test asserts equal keys, one workspace). |
| Mapped topic preserved | `mapPublicTopicToPrivate` resolves the public topic from the returned `topic_map`; the hook exposes `privateTopicId` and the client test asserts `pub_topic_async → item_async`. |
| Source snapshot unchanged | The client only reads the public snapshot and posts the save; the copy is server-produced. The public-route read is unchanged from LSI-030, and the save never issues a write to `/public/`. |
| Two generated copies isolated | A different template has no `sourceSnapshotRef` match, so the hook creates a distinct workspace; the backend namespaces private ids per `workspace:template:version` (LSI-028). |
| Save UI | `PublicCourseView` renders guest gate / signed-in action / pending / created / reused / error+retry; component and page tests cover each state. |
| Integrated snapshot/copy/progress refresh | The save hook announces a collection change; `useAuthorizedCurricula` refetches (dedicated test), so the copied roadmap (with its curriculum summary and progress) appears in the collection. |
| Out of scope honored (no unrelated intent replay) | No pending-intent storage or auth-callback replay is added; the gated guest action routes to sign-in only (LSI-032 owns intent resumption). |

## 6. Limitations

* A retry after a save failure reuses the workspace this hook instance created;
  across a full page reload the client re-lists workspaces and re-creates an
  empty one if the snapshot copy did not complete, which matches the LSI-028
  "client creates the empty workspace" model. No orphan copy is possible because
  the copy write is atomic and idempotent.
* "Open my copy" routes to the private workspace landing
  (`buildWorkspaceUrl`), which renders the ordered roadmap. Deep-linking the
  private course to the exact copied topic is intentionally left to the LSI-032
  intent (which carries topic/reading context); the mapped topic is exposed via
  `privateTopicId` for that purpose.
* The guest lesson reader's save-with-topic path is not wired here; LSI-031 saves
  the whole roadmap from the course surface, and the mapping helper is ready for
  the lesson/intent flow.
