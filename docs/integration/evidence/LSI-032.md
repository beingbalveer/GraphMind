## 1. Objective

Close the guest → learner journey that LSI-030/031 opened. A guest who tries a
private action on a public surface now stores exactly one discriminated, expiring
intent and is sent to sign in. After authentication the client revalidates the
source against the current published snapshot, performs the idempotent save, maps
the guest's topic onto the private copy, restores the guest's reading position,
and lands the learner on their own copy — **once**. Dismissal leaves nothing to
execute, a stale/forged callback is rejected without partial writes, practice
never auto-submits, and the tutor quote survives the round trip.

---

## 2. Design Decisions

* **The stored intent is untrusted input.** The executor never trusts the payload:
  it re-reads the published snapshot (`readPublicRoadmap`, the source of truth)
  and requires the template id, slug, and snapshot version to match it, and the
  referenced topic to still exist in it. A mismatch or a missing topic is
  **skipped with no write** and routes to catalog/roadmap. Primary identities
  never appear in a URL query string.
* **Public identities only.** An intent carries the public template/slug/version
  and public topic slug/id plus reading context — never a private workspace,
  roadmap, chat, or session id. Owner authorization happens server-side in the
  LSI-028 save service, so a forged payload can never apply partial private state.
* **Consume exactly once.** `consumePendingIntent` clears storage *before* the
  async resume runs, so a duplicate auth callback (or a React re-run) finds
  nothing and is a no-op. Dismissal is a plain `clearPendingIntent` — no write.
* **One shared save flow.** The executor reuses `performSaveRoadmapCopy` (extracted
  from the LSI-031 hook) with a fresh `SaveCopySession`, so reuse-vs-create,
  one idempotency key per `template:version`, and topic mapping behave identically
  to the signed-in save surface.
* **Reading context is real, not decorative.** The public lesson page measures the
  guest's scroll ratio at the moment of gating; the executor transfers it onto the
  copied topic's private reading-position key (`saveReadingPosition`), so the
  existing `useReadingPosition` restores it when the private lesson opens.
* **Practice never auto-submits; the tutor quote is carried, never sent.** A
  practice resume performs only the save-copy write; a tutor resume returns the
  quote as data on the outcome.
* **A stored intent while already signed in also resumes.** `storePendingIntent`
  broadcasts `graphmind:pending-auth-intent`; the resumer listens and acts, so the
  public lesson gate works for a learner who is already authenticated.
* **No backend change.** LSI-027 (public reads) and LSI-028 (idempotent,
  owner-authorized save) already provide everything the resume needs.

## 3. Changes Made

### 3.1 Intent model + store — `apps/web/src/lib/authIntent.ts` (new)
* Discriminated `PendingIntent` over `save | complete | practice | tutor |
  generator | signin`, each carrying `IntentMeta` (`createdAt`, `expiresAt`,
  `readingRatio`).
* `PENDING_INTENT_TTL_MS` (30 min) + `PENDING_INTENT_STORAGE_KEY`.
* `parsePendingIntent` validates untrusted JSON (rejects unknown kinds, missing
  per-kind context, malformed timestamps, expired payloads) and returns `null`
  instead of throwing. `isPendingIntent` / `isIntentExpired` guards.
* `storePendingIntent`, `readPendingIntent` (drops + clears expired/malformed),
  `clearPendingIntent`, `consumePendingIntent` (read-then-clear), and the
  `PENDING_INTENT_STORED_EVENT` broadcast + `subscribePendingIntentStored`.

### 3.2 Executor — `apps/web/src/lib/intentResume.ts` (new)
* `resumePendingIntent(intent, deps?)` with injectable `ResumeDeps` for tests.
* Revalidates the snapshot, resolves the topic against the current snapshot,
  performs the idempotent save, transfers the reading position, announces the
  collection change, and returns a `ResumeOutcome` (`kind`, `status`
  applied/skipped/failed, `destination`, `enrollment`, `privateTopicId`, `quote`,
  `readingRatio`, `message`). Never throws.

### 3.3 Resumer — `apps/web/src/components/auth/AuthIntentResumer.tsx` (new)
* Client component mounted once in the root layout inside `AuthProvider`. Consumes
  and resumes a stored intent on authentication, and on a new store while signed
  in; navigates to the outcome destination.

### 3.4 Layout + guest surfaces
* `apps/web/src/app/layout.tsx` — mounts `<AuthIntentResumer />` inside
  `AuthProvider`.
* `apps/web/src/app/learn/[slug]/page.tsx` — the guest save gate stores a `save`
  intent (public snapshot identity) before routing to sign-in.
* `apps/web/src/app/learn/[slug]/lessons/[topicSlug]/page.tsx` — the gated
  progress/tutor action stores a `signin` intent (snapshot + topic + measured
  reading ratio) and routes a guest to sign-in (a signed-in learner lets the
  resumer act).

### 3.5 Shared save flow — `apps/web/src/lib/enrollmentApi.ts`,
`apps/web/src/hooks/useSaveRoadmapCopy.ts`
* Extracted `performSaveRoadmapCopy`, `SaveCopyInput`, `SaveCopySession`,
  `SaveCopyOutcome`, `SaveCopyDeps`, and `createSaveCopySession` so the LSI-031
  hook and the LSI-032 executor share one resumable, idempotent flow.

### 3.6 Test infrastructure — `apps/web/src/test/setup.ts`
* jsdom under this Node version exposes no working `localStorage` (Node's own is
  experimental and needs `--localstorage-file`). Added a real in-memory
  `localStorage`, cleared after each test, so storage-backed flows are exercised
  rather than silently skipped.

### 3.7 Tests
* `apps/web/src/lib/__tests__/authIntent.test.ts` (9): store/expiry/broadcast,
  forged + partial + expired parsing, corrupt payload, consume-once, clear,
  guard.
* `apps/web/src/lib/__tests__/intentResume.test.ts` (11): generator, bare
  sign-in, save + revalidate + open, topic mapping + reading position, stale
  snapshot, forged template, unavailable roadmap, missing topic, tutor quote,
  practice (no submit), save failure.
* `apps/web/src/components/auth/__tests__/AuthIntentResumer.test.tsx` (3):
  resume + navigate + consume-once, no-op when unauthenticated, duplicate-callback
  safety.
* `apps/web/src/app/learn/__tests__/public-course-page.test.tsx` (+intent
  assertions): the guest save gate stores a `save` intent and writes nothing.
* `apps/web/src/app/learn/__tests__/public-lesson-page.test.tsx` (+intent
  assertions): the gated lesson action stores a `signin` intent (topic + reading
  context) and writes nothing.

## 5. Acceptance-Criteria Mapping

| Acceptance criterion | Evidence |
| :--- | :--- |
| Dismissal has no writes | The gated actions only store an intent + route to sign-in; no request is issued (course + lesson page tests assert zero mutations). Dismissal is `clearPendingIntent`, which performs no write (store test). |
| Callback revalidates source/owner and maps the copied topic | `resumePendingIntent` re-reads the published snapshot and requires id-multiset + topic to match before saving; owner authorization is the server's (LSI-028). `mapPublicTopicToPrivate` (via the save outcome) resolves `pub_topic_async → item_async` (executor test). |
| Practice does not auto-submit | A practice resume performs exactly one write (the save-copy) and returns `quote: null` (executor test); no attempt/answer call exists. |
| Tutor quote survives | The tutor resume returns the selected quote on the outcome and never sends it (executor test). |
| Duplicate callback safe | `consumePendingIntent` clears before executing; a re-render/duplicate callback finds nothing (store test + resumer duplicate-callback test). |
| Public identities only; no primary IDs in query params | Submitted/stored payloads are asserted to contain no `workspaceId`; destinations are `buildWorkspaceUrl(workspaceId)` (path), never a query param. |
| Guest → login journey | Course and lesson page tests exercise the guest gate → intent stored → sign-in URL; the resumer test exercises authenticated → resume → destination. |
| Out of scope honored | The executor treats callback payloads as untrusted (forged-template + stale-snapshot + missing-topic tests) and validates the published snapshot as authority. |

## 6. Limitations

* The private course is opened at the workspace landing (`buildWorkspaceUrl`); the
  mapped `privateTopicId`, quote, and reading ratio are carried on the outcome and
  the reading position is transferred into the private key. The private shell
  (`ChatContainer`) does not yet accept a topic selector or a pre-filled tutor
  quote, so the exact-topic/pre-filled-tutor delivery into the private UI is left
  to a follow-up on that surface. LSI-031's own limitation note anticipated the
  intent carrying this context; LSI-032 makes the intent real and consumable.
* `complete` and `practice` intents are fully modeled and executed, but the guest
  surfaces currently expose only the save gate (course) and the progress/tutor
  gate (lesson); a guest completion/practice control would reuse `storePendingIntent`
  with those kinds.
* The reading ratio is captured at the moment of gating from the lesson scroll
  container; a subsequent resume transfers it to the private topic key.
