## 1. Executive Summary & Objective

[LSI-033](../LEARNING_STUDIO_BACKLOG.md#lsi-033-files-and-attachments) is an **Epic E (Legacy parity)** ticket: *preserve* the already-exposed production file capabilities rather than build new UI. The production workspace file library (upload / list / category filter / client search / download / delete) and chat attachment ingestion (drag-drop, paste, file picker, and "Attach from Library") were already implemented end-to-end through the real `files` router and `FileService`, and the full-page library is reachable at the canonical `buildLibraryUrl(workspaceId)` route inside `ChatContainer`'s `library` view mode.

This ticket therefore:
1. **Verified and preserved** the existing library surfaces, the real `/api/v1/workspaces/{workspaceId}/files` API, and chat attachment ingestion through the real workspace file service. No runtime code was changed — the capability was already complete and wired; changing it would risk regressions against the "preserve existing" requirement. (see §5).
2. **Proved the private/public boundary by test**, which is the core acceptance criterion: private uploads are strictly workspace-scoped, every endpoint is gated by `require_workspace_read` / `require_workspace_write`, no endpoint serializes server storage paths, and a private upload can never be listed, read, downloaded, or deleted through another workspace or by a non-member.
3. **Added focused quality gates** that close the previously untested gaps: role-based authorization, cross-workspace isolation, upload error handling, extraction metadata, and the browser upload / attach journeys at the component level.

> **Runtime changes: none.** This ticket is verification + durable test evidence for an existing production capability, consistent with its "preserve existing… through real services" scope and the "reuse existing file services; do NOT create dead UI" instruction.

## 2. Existing Capability Inventory (verified, not modified)

### 2.1 Backend API — `apps/api/src/routers/files.py`
| Method | Path | Gate | Purpose |
|---|---|---|---|
| `POST` | `/api/v1/workspaces/{workspace_id}/files/upload` | `require_workspace_write` | Upload asset; `201`, or `400` on `ValueError` |
| `GET` | `/api/v1/workspaces/{workspace_id}/files` | `require_workspace_read` | List with `category` filter + `limit`/`offset` |
| `GET` | `/api/v1/workspaces/{workspace_id}/files/{file_id}` | `require_workspace_read` | File metadata (`404` if foreign/missing) |
| `GET` | `/api/v1/workspaces/{workspace_id}/files/{file_id}/download` | `require_workspace_read` | Raw bytes; inline or `?download=true` attachment |
| `DELETE` | `/api/v1/workspaces/{workspace_id}/files/{file_id}` | `require_workspace_write` | Delete DB row + physical asset |

- The response schema (`WorkspaceFileResponse`) exposes only `id/workspaceId/name/sizeBytes/mimeType/fileCategory/extractedText/createdAt/metadata/url`; **`storage_path` is never serialized**.
- `url` is always the workspace-scoped private download path; there is no anonymous/guest file route in `main.py` (only `auth/chat/workspaces/canvas/roadmap*/curriculum/mastery/curator/flashcards/files` are mounted).

### 2.2 Storage + extraction — `apps/api/src/services/file_service.py`
- Categorizes and extracts `document` / `tabular` (CSV/TSV/JSONL/XLSX→Markdown preview + `row_count`/`columns`), `code`, `image`, `other`; enforces the 20 MB limit; sanitizes filenames (`_sanitize_filename`, path-traversal safe); auto-chunks/indexes extracted text.

### 2.3 Web surfaces
- `apps/web/src/components/library/FileLibraryView.tsx` — full-page `/w/{workspaceId}/library` view (drop zone, `SegmentedTabs` categories, `Input` search, upload, `ConfirmDialog` delete, embedded PDF/table/code/image viewers).
- `apps/web/src/components/library/FileLibraryModal.tsx` — in-chat library picker (used by `ChatInput` "Attach from Library").
- `apps/web/src/components/chat/ChatInput.tsx` — drag/paste/pick attachment → `uploadWorkspaceFile()` (real service) → attachment chip → sent with the message.
- `apps/web/src/components/chat/ChatMessage.tsx` — renders message attachments (image/pdf/tabular/code) through the viewers.
- `apps/web/src/lib/workspaceApi.ts` — `fetchWorkspaceFiles`, `uploadWorkspaceFile`, `deleteWorkspaceFile`, `resolveFileUrl` against the real API.

## 3. Changes Made (tests + evidence only)

### 3.1 Backend — `apps/api/tests/test_files_lsi033.py` (new, 4 tests)
- `test_file_library_authorization_roles_and_private_isolation`: owner uploads; **viewer** member can list/get/download (`200`) but upload/delete return `403`; a **non-member** gets `404` on list/get/download/upload/delete; the original file is untouched after the forbidden attempts. Also asserts the advertised `url` is the canonical workspace-scoped private path.
- `test_private_upload_never_appears_in_another_workspace`: same owner, two workspaces — workspace B's listing never contains A's upload; direct get/download/delete through B return `404`; the payload never contains `storagePath`/`storage_path`; the file is still reachable inside A.
- `test_upload_errors_are_client_safe_and_processing_metadata_exposed`: oversized upload → `400` with a bounded message; missing workspace → `404`; a successful CSV upload surfaces `fileCategory="tabular"`, `metadata.row_count`, and the extracted Markdown table.
- `test_chat_attachment_ingestion_uses_real_workspace_file`: a real uploaded file (id + extracted text) is attached to a real `/api/v1/chat/completions` request and returns assistant content.

### 3.2 Frontend — `apps/web/src/components/library/__tests__/file-library-view.test.tsx`
- Added **upload journey**: selecting a file calls `uploadWorkspaceFile("ws-1", file)` and refreshes the library via `fetchWorkspaceFiles`, rendering the new file. (Existing list/search/status-badge/delete-dialog tests retained.)

### 3.3 Frontend — `apps/web/src/components/chat/__tests__/chat-input.test.tsx`
- Added **chat attachment ingestion journey**: attaching a file uploads it through `uploadWorkspaceFile("ws-1", file)`, renders the attachment chip, and `onSendMessage` receives the attachment array with the message. (Existing Enter/Shift+Enter and design-token tests retained.)
