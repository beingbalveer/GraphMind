## 1. Executive Summary & Objective

In accordance with [LSI-035](file:///Users/balveer/Projects/GraphMind/docs/integration/LEARNING_STUDIO_BACKLOG.md#lsi-035-flashcards-and-learning-message-actions), the existing flashcard message actions and their learning-message counterparts are preserved across the **root** conversation, the **branch** side peek, and the **canvas** node selection surface, without introducing local-only fake actions or changing flashcard ownership.

The flashcards feature was already production-native (it is listed in `LSI-001` as *"Not in prototype"*), so this ticket is a parity/verification ticket:

1. **One shared review surface (`FlashcardModal`) for all three surfaces.**
   - `ChatMessage` renders `FlashcardModal` for any completed, non-empty assistant message that has a workspace id.
   - The root stream (`ChatContainer`) and the branch/canvas side peek (`SidePeekBranchSheet`, opened by canvas node selection via `handleSelectTreeNode` → `handleOpenSidePeek`) both pass `workspaceId` and the resolved BYOK `flashcardGenerationConfig`, so generation uses the configured provider/model rather than silent server defaults.

2. **Exposed actions call real services.**
   - Review → `listNodeFlashcards` (`GET …/nodes/{nodeId}/flashcards`).
   - Generate → `generateNodeFlashcards` (`POST …/flashcards/generate`) with `count`/`replaceExisting` + BYOK config.
   - Edit → `updateNodeFlashcard` (`PATCH …/flashcards/{cardId}`).
   - Delete → `deleteNodeFlashcard` (`DELETE …/flashcards/{cardId}`) through the shared `ConfirmDialog`.
   - Regenerate → `generateNodeFlashcards` with `replaceExisting: true`.
   - Learning message actions (`LearningActions`) remain wired to `onLearningAction` → `handleSendBranchStream`, and are unchanged.

3. **Source node/workspace linkage and cascade semantics.**
   - Cards are addressed strictly by `(workspace_id, source_node_id, card_id)`; cross-node and cross-workspace access raises `FlashcardNotFoundError`/404.
   - Deleting a source branch (`WorkspaceService.delete_branch`, raw recursive `DELETE FROM nodes`) and deleting a workspace (`WorkspaceService.delete_workspace`, ORM delete) cascade away every linked flashcard via the `ON DELETE CASCADE` foreign keys. No orphaned cards remain.

4. **No ownership or contract changes.**
   - No schema, model, router, service, or component behaviour was modified. No new capability was invented.

## 2. Changes Made

### 2.1 Backend cascade/linkage suite (`apps/api/tests/test_flashcard_cascade.py`, new)
* `test_deleting_source_branch_cascades_flashcards`: seeds a workspace with a parent + descendant assistant node, generates a card on each, deletes the branch via `WorkspaceService.delete_branch`, and asserts both nodes and both cards are gone.
* `test_deleting_workspace_cascades_flashcards`: seeds a workspace with cards, deletes it via `WorkspaceService.delete_workspace`, and asserts the workspace and all its cards are gone.
* `test_flashcard_linkage_is_scoped_to_source_node_and_workspace`: asserts each card keeps its exact `source_node_id`/`workspace_id`, that a card cannot be updated/deleted through a sibling node, and that a node from another workspace is not reachable.
* Uses the shared session factory and the isolated `*_test` database enforced by `apps/api/tests/conftest.py`; the LLM provider is mocked.

### 2.2 Frontend cross-surface journey suite (`apps/web/src/components/flashcards/__tests__/flashcard-cross-surface-lsi035.test.tsx`, new)
* Root-surface journey: renders `ChatMessage` exactly as `ChatContainer` does (with `workspaceId` + `flashcardGenerationConfig`), opens the study drawer, and drives **generate → edit → delete → regenerate**, asserting each call reaches the corresponding `@/lib/flashcardApi` service with the correct workspace/node/card ids and the BYOK config.
* Branch/canvas-surface journey: renders `SidePeekBranchSheet` as used by both the nested branch side peek and canvas node selection (with `workspaceId` + `flashcardGenerationConfig`), asserts the review trigger is exposed for the branch assistant node, and asserts list/generate call the service with the branch node id and forward BYOK config.

### 2.3 No runtime changes
* No production source files were modified. The live surfaces already routed through the shared `FlashcardModal`, `FlashcardItem`, `flashcardApi`, and `FlashcardService`; the new tests lock that contract and the cascade behaviour.
