## 1. Executive Summary & Objective

In accordance with [LSI-036](file:///Users/balveer/Projects/GraphMind/docs/integration/LEARNING_STUDIO_BACKLOG.md#lsi-036-direct-edits-and-revision-history), the Learning Studio surfaces (Lesson, List, Canvas) now expose the existing **topic editor, revision history, diff, and restore** contracts with a single current-revision projection:

1. **Reuse of existing contracts (no new revision semantics):**
   - A new `StudioRoadmapEditing` component reuses the existing `TopicEditor` (update/add/move/remove/schedule/resources patches) and `RevisionHistory` (history, archived topics, restore) components verbatim.
   - Optimistic concurrency (`REVISION_CONFLICT`, HTTP 409), history-removal acknowledgement (`HISTORY_REMOVAL_ACK_REQUIRED`), and the "reload latest" recovery affordances are inherited unchanged, so an edit never silently overwrites a newer revision.
2. **Coherent Lesson/List/Canvas projection:**
   - All three Studio surfaces render from a single `CurriculumView`; the freshly saved/restored server view is reported up through `onSaved`, so the Lesson reader, phased List, and 2D Canvas update to the same current revision together.
   - `StudioCourseListView` offers topic creation + revision history; `StudioLessonReader` offers a lesson-scoped "Edit lesson" action.
3. **Stale-edit recovery:**
   - A stale save surfaces the existing conflict alert and retains the draft; "Reload latest and discard draft" (editor) and "Reload latest" (history) recover the authoritative revision without overwriting.
4. **Progress mapping follows existing policy:**
   - Completion continues to be scoped to stable workspace/revision/topic identities and is preserved across edits, moves, and restores; the returned server view carries authoritative progress into the Studio projection.

## 2. Changes Made

### 2.1 Studio editing entry point (reuses existing editor + history)
* `apps/web/src/components/studio/StudioRoadmapEditing.tsx` (new):
  - `DropdownMenu` action cluster exposing "Edit lesson" (when a `topicId` is supplied), "Add topic", and "Revision history".
  - Renders the existing `TopicEditor` and `RevisionHistory`, forwarding `onSaved` (current-revision projection) and `onReload` (stale-edit recovery).
  - Hidden for read-only (`canWrite === false`) views; uses `@/components/ui/button` and `@/components/ui/dropdown-menu` with semantic tokens only.

### 2.2 List & Canvas integration
* `apps/web/src/components/studio/StudioCourseListView.tsx`:
  - Added optional `onSaved` / `onReload` props and embedded `StudioRoadmapEditing` in both the list header and the canvas top bar.

### 2.3 Lesson integration
* `apps/web/src/components/studio/StudioLessonReader.tsx`:
  - Added optional `view` / `onSaved` / `onReload` props and a lesson-scoped `StudioRoadmapEditing topicId={topic.id}` control in the lesson header.

### 2.4 Single current-revision projection in the Studio harness
* `apps/web/src/app/studio-preview/page.tsx`:
  - Curriculum view is now state (`curriculumView`) with `applySavedView` syncing the returned revision + progress into the Lesson/List/Canvas projection, and `reloadCurriculum` performing an authoritative reload.

### 2.5 Tests
* `apps/api/tests/roadmap/test_direct_edits.py` (new): 3 API-boundary tests covering stale-edit conflict (no silent overwrite), history preservation, progress-preserving edit + restore, and that a rejected restore creates no revision.
* `apps/web/src/components/studio/__tests__/StudioRoadmapEditing.test.tsx` (new): 4 vitest tests covering lesson edit projection, stale-edit reload recovery (draft retained), revision-history undo, and coherent Lesson + List projection after an edit.
