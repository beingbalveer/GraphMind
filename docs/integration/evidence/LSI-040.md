## 1. Executive Summary & Objective

In accordance with [LSI-040](file:///Users/balveerd/Documents/AI/GraphMind/docs/integration/LEARNING_STUDIO_BACKLOG.md#lsi-040-general-workspaces-and-management), the existing general (non-curriculum) workspace surface was completed and locked without replacing any workspace identity or altering the canonical URL contract:

1. **Dashboard create / select / rename / delete.** The production dashboard (`/`, `WorkspaceDashboard`) already created and selected workspaces by canonical `buildWorkspaceUrl`. It now also **renames** and **deletes** workspaces through the existing `PATCH`/`DELETE /workspaces/{id}` contract, using only shared `@/components/ui` primitives (`DropdownMenu`, `Modal`, `Input`, `ConfirmDialog`, `Button`, `InlineFeedback`) and semantic design tokens.
2. **Delete confirmation and membership errors.** Destructive deletion is gated by the shared `ConfirmDialog`; a viewer/non-member denial surfaces an actionable membership message and leaves the workspace intact.
3. **Ordinary route behavior under `ROADMAP_NOT_FOUND`.** An ordinary workspace keeps its metadata, chat landing, new-chat creation, and graph when the curriculum read returns a typed `ROADMAP_NOT_FOUND`. The client already maps that code to an ordinary (no-roadmap) state; this ticket adds an end-to-end backend lock.
4. **Anchor rules hold.** The protected roadmap canvas anchor chat still returns `409 ROADMAP_ANCHOR_PROTECTED` on the chat-delete route, while deleting the authorized workspace still removes the roadmap via the existing cascade.

No new workspace, chat, or URL identities were introduced. `dashboard-preview` (a static, public design preview with mock data) was intentionally left untouched to avoid adding dead UI; the real management behavior lives on the production dashboard.

## 2. Changes Made

### 2.1 Workspace API Client (`apps/web/src/lib/workspaceApi.ts`)
* Added `renameWorkspace(workspaceId, name): Promise<WorkspaceItem>` — a thin wrapper over the existing `PATCH /workspaces/{id}` contract. It resolves with the server's authoritative workspace (same `id`, new `name`) and rejects on failure so callers can distinguish success from a membership denial. Existing helpers (`createWorkspace`, `deleteWorkspace`, `fetchWorkspaces`) were reused unchanged.

### 2.2 Production Dashboard (`apps/web/src/components/workspace/WorkspaceDashboard.tsx`)
* Added a per-card management `DropdownMenu` (Rename / Delete) rendered as a **sibling** of the clickable card so no interactive control is nested inside the `role="button"` surface.
* **Rename:** opens a shared `Modal` + `Input`; `Save` calls `renameWorkspace` and updates the projected row **in place**, preserving the workspace id and therefore every canonical `/w/{id}/...` link. `Enter` submits; blank names are rejected.
* **Delete:** opens the shared `ConfirmDialog` with the workspace name and cascade warning; confirming calls `deleteWorkspace` and removes the row, cancelling makes no request.
* **Membership-aware errors:** `describeManagementError` maps `403` → "Only owners and editors can…" and `404` → "no longer exists or you are not a member", surfaced through `InlineFeedback` without mutating the list.
* All navigation continues to use `buildWorkspaceUrl` from `@/lib/urls`; no URL string is hardcoded (locked by test).

### 2.3 Frontend Tests (`apps/web/src/components/workspace/__tests__/workspace-management.test.tsx`, new)
* 5 focused tests: rename keeps the identity + canonical URL; delete requires confirmation; cancelled delete makes no request; a `403` rename surfaces the membership error and leaves the workspace intact; the component contains no hardcoded `/w/` path and routes through the URL helper.

### 2.4 Backend Tests (`apps/api/tests/roadmap/test_general_workspaces.py`, new)
* 3 focused acceptance tests against the isolated `*_test` database:
  * ordinary workspace create → select → rename → delete preserves the original id;
  * `ROADMAP_NOT_FOUND` on an ordinary workspace while metadata/chats/graph still work;
  * anchor deletion refused (`409 ROADMAP_ANCHOR_PROTECTED`), non-member/viewer management writes denied (`404`/`403`), editor rename allowed, and owner workspace delete cascades the roadmap away.

## 4. Acceptance Mapping

* **Original IDs / workspaces remain accessible:** `test_ordinary_workspace_management_preserves_identity` asserts the created id is readable directly and via the listing, survives a rename unchanged, and then 404s only after its own delete. The dashboard rename test asserts the id (and therefore the `/w/{id}` URL) is unchanged after rename.
* **`ROADMAP_NOT_FOUND` preserves ordinary behavior:** `test_roadmap_not_found_preserves_ordinary_workspace_behavior` asserts a typed 404 `ROADMAP_NOT_FOUND` on the curriculum route while workspace metadata, the empty chat list, new root-chat creation, and the graph snapshot all return 200. The existing `useRoadmap` test locks the client's ordinary-absence handling.
* **Delete confirmation:** `WorkspaceDashboard` routes deletion through the shared `ConfirmDialog`; the vitest test asserts no `deleteWorkspace` call before confirming and that cancelling makes none.
* **Membership rules hold:** `test_anchor_membership_and_workspace_cascade` asserts a non-member is denied rename/delete (`404`), a viewer is denied (`403`), and an editor may rename. The dashboard surfaces an actionable membership error on `403`.
* **Anchor rules hold:** the same backend test asserts `DELETE /workspaces/{id}/chats/{anchor}` returns `409 ROADMAP_ANCHOR_PROTECTED`, and that deleting the workspace removes the roadmap (`GET /roadmap` → 404) through the existing cascade.
* **URL contract unchanged:** the component uses `buildWorkspaceUrl` only and contains no hardcoded `/w/` path (locked by test). No workspace, chat, or redirect identity was changed.
