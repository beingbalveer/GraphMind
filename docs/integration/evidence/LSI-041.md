## 1. Executive Summary & Objective

In accordance with [LSI-041](file:///Users/balveerd/Documents/AI/GraphMind/docs/integration/LEARNING_STUDIO_BACKLOG.md#lsi-041-search-and-semantic-discovery), inventory-backed graph + hybrid search was exposed end-to-end so that a learner can discover knowledge inside an authorized workspace and open every result in its canonical context:

1. **One unified, permission-scoped endpoint.** A new `POST /workspaces/{workspace_id}/search` composes the **already-exposed** retrieval services instead of introducing a new discovery engine: `SemanticService.search_workspace_nodes` (pgvector cosine over embedded conversation nodes — the "graph" leg) and `RAGService.hybrid_search` (dual dense + sparse over embedded file chunks — the "hybrid" leg). Both legs run under a single `require_workspace_read` membership check, so results never cross a workspace boundary.
2. **Results carry canonical identity.** Every node hit is enriched with its conversation root as `chatId`, resolved in memory from the workspace's `parent_id` map, so a hit opens `/w/{workspaceId}/chat/{chatId}?node={nodeId}`. Every file hit carries its `fileId`, so it opens `/w/{workspaceId}/library?file={fileId}`.
3. **Production surfacing, no dead UI.** The existing production Command Palette (⌘K) was upgraded to run the scoped server search alongside its local in-conversation filter, with **Workspace conversations** and **Files** sections, per-section navigation, and honest loading / empty / error+retry states. No new route, placeholder panel, or unused control was added.
4. **Result navigation to canonical context.** Selecting a node result pushes the canonical chat deep link; selecting a file result pushes the library route, where `FileLibraryView` highlights (`ring-2 ring-primary/40`) and scrolls the deep-linked file into view.

No new search identity, URL, or storage contract was introduced, and no enterprise discovery feature beyond the already-exposed retrieval services (the ticket's out-of-scope clause) was added.

## 2. Changes Made

### 2.1 Backend Response Schemas (`apps/api/src/schemas/workspace.py`)
* Added `SearchNodeHit` (`node_id`, `chat_id`, `role`, `content`, `highlighted_context`, `similarity_score`, `created_at`, `metadata`), `SearchFileHit` (`file_id`, `filename`, `chunk_id`, `chunk_index`, `snippet`, `page_number`, `section_header`, `score`), and `WorkspaceSearchResponse` (`workspace_id`, `query`, `nodes`, `files`, `total_nodes`, `total_files`).
* All three extend the existing `BaseSchema`, so the response serializes with camelCase aliases (`workspaceId`, `nodeId`, `chatId`, `fileId`, …) consistent with the rest of the API.

### 2.2 Unified Search Service (`apps/api/src/services/search_service.py`, new)
* `SearchService.search(db, workspace_id, query, top_k, min_similarity)` runs both legs for one authorized workspace.
* Empty / whitespace-only queries return an explicit empty `WorkspaceSearchResponse` (200) instead of erroring, so the client can render an honest empty state.
* `top_k` is clamped to `[1, MAX_RESULTS=20]` to bound fan-out; file snippets are trimmed to `SNIPPET_LENGTH=280`.
* `_resolve_root_chat_ids` reads the workspace node graph once and walks `parent_id` **in memory** (cycle-safe) to map every node to its conversation root — avoiding one ancestor query per hit — and node hits fall back to their own id when no root is found.
* Emits a structured log line (`workspace_id`, query, node/file result counts).

### 2.3 Workspace Router (`apps/api/src/routers/workspaces.py`)
* Added `POST /{workspace_id}/search` with `response_model=WorkspaceSearchResponse`, guarded by `Depends(require_workspace_read)`, reusing the existing `SemanticSearchRequest` body. The pre-existing `/{workspace_id}/search/semantic` route was left untouched.
* Added imports for `SearchService` and `WorkspaceSearchResponse`.

### 2.4 Web Search Client (`apps/web/src/lib/searchApi.ts`, new)
* `searchWorkspace(workspaceId, query, { topK, minSimilarity, signal })` posts `{ query, topK, minSimilarity }` to `/workspaces/{id}/search` via the shared `apiFetch`, merging the caller's `AbortSignal`. Rejects on failure so callers can distinguish "no matches" from "could not search".
* `searchNodeResultUrl` / `searchFileResultUrl` build canonical URLs **only** through `@/lib/urls` (`buildNodeUrl`, `buildLibraryUrl`).

### 2.5 Canonical URL Helper (`apps/web/src/lib/urls.ts`)
* `buildLibraryUrl(workspaceId, params?: { file?: string })` now emits `/w/{workspaceId}/library?file={encodedFileId}` when a file id is supplied; the no-parameter behavior is unchanged.

### 2.6 Command Palette (`apps/web/src/components/canvas/CommandPalette.tsx`)
* New optional props `workspaceId` and `onNavigateResult(url)`.
* Debounced (250 ms) server search firing once the trimmed query reaches 2 characters, scoped to the authorized workspace, with `AbortController` cancellation on query change / close / unmount.
* Renders **This conversation** (existing local filter), **Workspace conversations** (node hits with percent score) and **Files** (filename + snippet) sections; keyboard `↑/↓/Enter` navigation spans local, node, file, then action rows.
* Explicit states: a spinner while searching, an `alert` + "Retry search" action on failure (retry via a nonce re-trigger), and a "No matching results" status block on a successful empty result. Selecting a result calls `onNavigateResult` with the canonical URL and closes the palette.

### 2.7 Container Wiring (`apps/web/src/components/chat/ChatContainer.tsx` & `apps/web/src/components/library/FileLibraryView.tsx`)
* `ChatContainer` passes `workspaceId={currentWorkspace?.id}` and `onNavigateResult={(url) => router.push(url)}` to `CommandPalette`, and `focusFileId={searchParams.get("file") ?? undefined}` to `FileLibraryView`.
* `FileLibraryView` gained an optional `focusFileId` prop: the matching card receives `border-primary ring-2 ring-primary/40`, is held in a ref, and is scrolled into view once files load; other cards keep the default treatment.

### 2.8 Tests
* **Backend** (`apps/api/tests/test_search_discovery.py`, new): 3 acceptance tests against the isolated `*_test` database — scoped node+file results with root resolution, permission scoping, and empty/unknown states.
* **Frontend** (`apps/web/src/components/canvas/__tests__/command-palette-search.test.tsx`, new): 5 tests — node deep link, file library link, empty state, error + retry, and no server call without a workspace.
* **Frontend** (`apps/web/src/lib/__tests__/searchApi.test.ts`, new): 2 tests — camelCase request body and canonical node/file URL construction through the real URL helpers.
* **Frontend** (`apps/web/src/components/library/__tests__/file-library-focus.test.tsx`, new): 1 test — deep-linked file is highlighted and scrolled, non-focused cards are not.

## 4. Acceptance Mapping

* **Results are permission-scoped:** `test_search_is_permission_scoped` asserts the owner receives `200` while a non-member receives `404`, and the endpoint is guarded by `Depends(require_workspace_read)`. Both retrieval legs receive only the single `workspace_id` they were authorized for, so no cross-workspace row can be returned.
* **Node results open canonical context:** `searchNodeResultUrl` routes through `buildNodeUrl`, producing `/w/{workspaceId}/chat/{chatId}?node={nodeId}`; `test_search_returns_scoped_node_and_file_results` asserts the node leg resolves the exact node to its conversation root (`chatId == root_id`, all hits share the root), and the palette test `opens a workspace node result through its canonical chat deep link` asserts `onNavigateResult` receives `buildNodeUrl("ws-1", "chat-1", "node-1")` and the palette closes.
* **File results open canonical context:** `searchFileResultUrl` routes through `buildLibraryUrl(ws, { file })` → `/w/{workspaceId}/library?file={fileId}`; the palette test `opens a file result in the workspace library context` asserts the exact URL, and `FileLibraryView ?file= focus` asserts the deep-linked card is highlighted (`ring-2`) and scrolled into view while others are not. The backend file leg asserts the returned `fileId`/`filename`/`snippet` provenance.
* **Empty state works:** `test_search_empty_and_unknown_states` asserts a whitespace query returns `200` with empty `nodes`/`files`; the palette `renders an empty state when the workspace has no matches` test asserts the "No matching results" status, and `does not call the server search when no workspace is provided`.
* **Error state works:** `test_search_empty_and_unknown_states` asserts an unknown workspace returns `404`; the palette `surfaces a search error and recovers on retry` test asserts an `alert` with the error message and that "Retry search" re-issues the request and renders the result. The `2xx/error` distinction is preserved because `searchWorkspace` rejects rather than returning an empty payload.
* **Reuse, not reinvention:** the service composes `SemanticService.search_workspace_nodes` and `RAGService.hybrid_search` (regression-locked in §3.2); no new retrieval engine, index, or migration was added.
* **URL contract + design rules:** every result URL is built by `@/lib/urls` (no hardcoded paths); the palette and library focus use shared `@/components/ui` primitives and semantic tokens (`bg-surface`, `text-foreground-muted`, `border-border`, `text-destructive`, `text-2xs`).
