## 1. Objective

Preserve the existing timeline / heatmap / replay entry points, the selected
state, and the return to the current graph. The history must be **scoped** to the
workspace, **playback must never mutate** the current nodes/progress, and a
**keyboard exit** must return to the current view.

This is a parity/verification ticket — the timeline projection, the replay
viewport, and the backend history endpoint already exist and are read-only — with
one real gap fixed: replay could only be exited with a pointer, so its acceptance
criterion for a keyboard exit was unmet.

---

## 2. Existing capability verified (no code change)

* **Scoped history (backend)** — `CuratorService.get_workspace_timeline`
  (`apps/api/src/services/curator_service.py`) queries `NodeModel` and
  `ConceptModel` filtered by `workspace_id`, so a timeline only ever projects the
  target workspace's own nodes/branches/concepts. `routers/curator.py`
  `GET /workspaces/{workspace_id}/curator/timeline` is guarded by
  `require_workspace_read` (owner/editor/viewer membership).
* **Read-only playback (frontend)** — `GraphCanvas.tsx` keeps replay layout in a
  separate `replayLayout` state (`setReplayLayout` instead of `stored.setLayout`),
  passes `readOnly={replay || !stored.ready}` to `CanvasSurface` (disabled drag /
  connect / auto-layout), and drops `onDelete` while replaying. Scrubbing only
  changes `eventIndex`; the live tree and stored layout are never written.
* **Entry points & state selection** — the canvas advanced menu toggles
  "Open timeline" / "Exit timeline"; `TimelineReplayBar` exposes play/pause,
  speed, milestone jump, scrubber, and an explicit Close/Exit button; the replay
  timestamp drives `filterConversationByTime` for the visible projection.
* **Projections (frontend)** — `filterConversationByTime` is covered by
  `conversationProjection.test.ts` (undated messages/ancestor chain retained,
  invalid timestamp is a no-op).

## 3. Changes Made

### 3.1 Runtime fix — `apps/web/src/components/canvas/GraphCanvas.tsx`

Added an Escape-key handler scoped to replay mode: while `replay` is active a
window `keydown` listener clears replay and stops playback, returning the viewport
to the current graph. The listener is removed when replay ends, so it never
interferes with other Escape handlers (command palette, drawers).

### 3.2 Tests

* `apps/web/src/components/canvas/__tests__/canvas-interactions.test.tsx` (+1) —
  opening the timeline, scrubbing to a point where a branch is not yet visible,
  pressing `Escape`, and confirming the replay bar is dismissed and the current
  branch (`segment:x`) is restored — i.e. keyboard exit returns to the current
  view without mutating it.
* `apps/api/tests/test_timeline_replay.py` (+2) — the timeline for one workspace
  contains only its own node entity IDs and never a sibling workspace's; a
  non-member cannot read another user's timeline history (`403`/`404`).

## 5. Acceptance-Criteria Mapping

| Acceptance criterion | Evidence |
| :--- | :--- |
| History is scoped | `test_workspace_timeline_is_scoped_to_its_own_history` proves each workspace's timeline contains only its own node entity IDs; the service filters by `workspace_id`. |
| Playback never mutates current nodes/progress | `GraphCanvas` writes replay positions to `replayLayout`, not the persisted layout; `CanvasSurface` receives `readOnly` and delete is disabled during replay; `canvas-interactions.test.tsx` "restores manual branch positions after read-only timeline replay" proves the stored layout is restored after exit. |
| Keyboard exit returns to current view | New `GraphCanvas` Escape handler + `canvas-interactions.test.tsx` "exits timeline replay with the Escape key and returns to the current graph". |
| Entry points / state selection preserved | Advanced menu "Open timeline"/"Exit timeline", `TimelineReplayBar` controls, and the projection tests are unchanged and green. |
| Read permission enforced on history | `test_workspace_timeline_requires_read_access` asserts a non-member gets `403`/`404`; the endpoint depends on `require_workspace_read`. |
| Timeline projections correct | `conversationProjection.test.ts` retains undated messages/ancestor chain and no-ops on an invalid timestamp. |
