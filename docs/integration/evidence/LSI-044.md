## 1. Objective

Implement the approved authenticated preference persistence (`GET`/`PUT
/api/v1/users/me/preferences`, LSI-002 §8) and port the visible theme / reading /
motion / study-hours / tutor-style effects. Ownership and version must be
validated, promised preferences must survive reload/session, and unsupported
demo-only settings must be removed.

Before this ticket there was **no** preferences endpoint and the Settings
"General"/"Appearance" tabs only contained disabled, demo-only placeholders.

---

## 2. Changes Made

### 2.1 Backend — persistence, ownership, concurrency

* `apps/api/src/models/user.py` — new `UserPreferences` table (one row per
  account, PK/FK `user_id`, cascade delete) with `theme`, `reading_font_size`,
  `reduced_motion`, `default_study_hours`, `tutor_style`, and an integer
  `version`; registered in `models/__init__.py`.
* `apps/api/alembic/versions/20261016_0009_add_user_preferences.py` — additive
  migration (single head `20261016_0009`), no data backfill.
* `apps/api/src/schemas/preferences.py` — approved enums/ranges
  (`light|dark|system`, `sm|md|lg`, `concise|socratic|detailed`, hours
  `0.5–80`) with camelCase aliases.
* `apps/api/src/services/preferences_service.py` — `get_or_create` (defaults on
  first read) and `update` with optimistic concurrency (`PreferenceConflictError`
  when the supplied version is stale).
* `apps/api/src/routers/users.py` — `GET`/`PUT /api/v1/users/me/preferences`,
  both self-scoped to the authenticated account via `get_current_user`; a stale
  version returns `409 Conflict`. Registered in `main.py`.

### 2.2 Frontend — client, effects, settings

* `apps/web/src/lib/preferencesApi.ts` — typed contract, approved defaults,
  study-hours bounds, and per-style tutor directives.
* `apps/web/src/lib/applyPreferences.ts` — pure `resolveIsDark` /
  `applyPreferences` mapping onto the document root (`dark` class,
  `data-reading-size`, `data-reduced-motion`).
* `apps/web/src/context/PreferencesContext.tsx` — `PreferencesProvider` loads
  the account's preferences, applies the visible effects (re-applying on OS
  color-scheme change), and exposes `save()`; safe default context so guests and
  tests get approved defaults with a no-op save. Mounted in `app/layout.tsx`.
* `apps/web/src/app/globals.css` — reading-size font scale for `.reading-text`
  and a `data-reduced-motion="true"` rule keyed off the root attributes.
* `apps/web/src/components/settings/SettingsPage.tsx` — real **Appearance**
  (theme, reading size, reduced motion) and **Learning preferences** (weekly
  study hours, tutor response style) controls; the disabled demo-only
  placeholders ("Auto-scroll", "Math rendering", "Compact density" and the
  "planned for a future release" copy) are removed. Saving persists the changed
  preferences through the injected handler.
* `apps/web/src/components/chat/ChatContainer.tsx` — passes the loaded
  preferences and the `save` handler into `SettingsPage`.
* `apps/web/src/components/studio/StudioRoadmapGenerator.tsx` — seeds a blank
  goal form from the persisted study hours when no explicit default is given.
* `apps/web/src/components/studio/StudioTutorChat.tsx` — appends the persisted
  tutor-style directive to the tutor system prompt.

## 4. Acceptance-Criteria Mapping

| Acceptance criterion | Evidence |
| :--- | :--- |
| Ownership validated | Routes use `get_current_user` and are self-scoped; `test_preferences_are_scoped_to_the_owning_account` proves one account's save never affects another's. |
| Version validated | `UserPreferences.version` + `test_stale_version_is_rejected_with_conflict` (stale `PUT` → `409`, stored value unchanged). |
| Promised preferences survive reload/session | `test_update_preferences_persists_across_reload_and_bumps_version` re-reads the value from a fresh request; `PreferencesContext.test.tsx` loads them and re-applies the effects on mount. |
| Unsupported demo-only settings removed | SettingsPage test asserts "Auto-scroll", "Math rendering", "Compact density", and "planned for a future release" are gone, replaced by persisted controls. |
| Visible theme/reading/motion effects | `applyPreferences`/`PreferencesContext.test.tsx` lock the `dark` class, `data-reading-size`, and `data-reduced-motion` outputs; `globals.css` consumes the attributes. |
| Study-hours effect | `StudioRoadmapGenerator` seeds the goal form from the persisted hours; `preferences-settings` proves the value is persisted. |
| Tutor-style effect | `StudioTutorChat` appends the persisted directive to the tutor system prompt; directives are locked by `preferences.test.ts`. |

## 5. Limitations

* Live preference round-trips against a themed production account are covered
  by the migration/asset gate (LSI-046); this ticket evidences the API + rendered
  effects only.
* The system-theme OS change listener uses `matchMedia`; environments without it
  fall back to light (defaults still applied).
* `SettingsModal` (the unused legacy modal) is intentionally untouched; obsolete
  learner UI retirement is LSI-050.
