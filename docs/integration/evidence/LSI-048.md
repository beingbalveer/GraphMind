## 4. Metrics to measure (definitions)

| Metric | Definition | Evidence artefact |
| :--- | :--- | :--- |
| **Grounding** | For a researched roadmap job: every topic's sources are real, fetchable public URLs with recorded citations; no fabricated references. | Job references (`GET /api/v1/roadmap/jobs/{id}/references`) + job events. |
| **Coverage** | Fraction of the goal's expected subtopics represented in the generated curriculum (phases/topics), independent of pacing. | Generated `roadmap` revision projection. |
| **Clarification** | The clarification round trip asks only necessary questions and the answers change the output; stale/duplicate answers are safe. | `POST /api/v1/roadmap/jobs/{id}/answers` events. |
| **Cancellation** | A cancel during generation stops publication; no partial curriculum is published; stale attempts are fenced. | `POST /api/v1/roadmap/jobs/{id}/cancel` + events (`cancel`/`failed`). |
| **Recovery** | After a failed/cancelled/interrupted job, retry resumes with the saved profile and budgets; the failed profile stays editable. | `POST /api/v1/roadmap/jobs/{id}/retry` + `resume`/`retry` events. |

## 5. Live run procedure (operator runbook)

> Run from the repo root. Export the same provider configuration the app uses. Keep a
> raw capture; redact **before** committing (§6). Label the run `LIVE`, not mocked.

```bash
# 0. Prerequisites: Postgres + Redis up; .env populated with real provider keys.

# 1. Start API and the researched-roadmap worker.
uv run --project apps/api uvicorn main:app --app-dir apps/api/src --port 8000 &
ENVIRONMENT=development PYTHONPATH=apps/api/src \
  uv run --project apps/api python -m services.roadmap.worker &

# 2. Authenticate (register/login) and keep the bearer token in $TOKEN.
#    See apps/api/src/routers/auth.py for the register/login routes.

# 3. Create + start a researched roadmap job for a representative goal.
curl -sS -X POST localhost:8000/api/v1/roadmap/jobs \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"prompt":"I want to learn backend engineering","title":"Backend Engineering"}' \
  | tee capture/create.json
JOB=$(python -c "import json,sys;print(json.load(open('capture/create.json'))['id'])")
curl -sS -X POST "localhost:8000/api/v1/roadmap/jobs/$JOB/start" \
  -H "Authorization: Bearer $TOKEN" | tee capture/start.json

# 4. Stream the job events (grounding/coverage/clarification/cancellation/recovery).
curl -sS -N "localhost:8000/api/v1/roadmap/jobs/$JOB/events" \
  -H "Authorization: Bearer $TOKEN" | tee capture/events.sse

# 5. Capture the references (grounding) once the job completes.
curl -sS "localhost:8000/api/v1/roadmap/jobs/$JOB/references" \
  -H "Authorization: Bearer $TOKEN" | tee capture/references.json

# 6. Tutoring journey: send a message and capture the SSE stream.
curl -sS -N -X POST localhost:8000/api/v1/chat/stream \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"message":"Explain event loops","workspace_id":"'"$WS"'"}' | tee capture/tutor.sse

# 7. Repeat steps 3–6 for the second provider, and exercise cancel/retry on one run.
```

Then, per metric, record a **redacted** excerpt and a verdict in a new copy of §7.

## 6. Redaction (automatable tooling — this commit)

`apps/api/src/evaluation/redact.py` is a deterministic, dependency-free redactor for
captured evidence. It is idempotent so a reviewer can re-run it and get byte-identical
output.

Redacts: provider-key shapes (Google `AIza…`, OpenAI `sk-…`, GitHub `ghp_…`, Slack
`xox…`, JWTs), `Authorization: Bearer …`, inline `api_key`/`secret`/`token`
assignments, JSON values under secret-named keys, and email local parts (domain kept).
It preserves benign evidence (coverage %, token-usage metrics, URLs, UUIDs).

```bash
# Redact a captured JSON file:
PYTHONPATH=apps/api/src uv run --project apps/api python -m evaluation.redact capture/create.json > capture/redacted/create.json
# Redact free-form logs (stdin → stdout):
cat capture/events.sse | PYTHONPATH=apps/api/src uv run --project apps/api python -m evaluation.redact > capture/redacted/events.sse

# Smoke test:
printf '{"provider":"gemini","api_key":"AIza...","note":"user@example.com","token_count":42}' \
  | PYTHONPATH=apps/api/src uv run --project apps/api python -m evaluation.redact
# → provider=gemini; api_key=[REDACTED]; note=u***@example.com; token_count=42 preserved
```

Covered by `apps/api/tests/test_redact_evidence.py` (8 tests): token shapes, bearer +
inline secrets, email local-part redaction, benign-content preservation, idempotency,
structured JSON key/​value redaction, and the CLI (file + stdin).
